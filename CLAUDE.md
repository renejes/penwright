# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

vswrite-desktop is a standalone Electron desktop app for WYSIWYG editing of Typst documents, ported from the vswrite VS Code extension. Tech stack: Electron 41, electron-vite 5, Svelte 5 (runes), TipTap/ProseMirror 3, simple-git, pdf.js. Typst CLI is bundled with the app (no user installation needed).

The app is **project-first**: every file lives inside a project folder. Each project is self-contained — the Git history (`.git/`), auto-backups (`.vswrite/backups/`), AI-edit snapshots (`.vswrite/ai-snapshots/`), and per-project UI preferences (`.vswrite/preferences.json`) all live inside the project, so copying or moving the folder takes the full state with it. The app starts at the Start Screen and never auto-reopens a project.

## Commands

```bash
# Development (the `unset ELECTRON_RUN_AS_NODE` prefix is required when running from VS Code/Cursor terminals)
unset ELECTRON_RUN_AS_NODE && electron-vite dev

# Build
unset ELECTRON_RUN_AS_NODE && electron-vite build

# Preview built app
unset ELECTRON_RUN_AS_NODE && electron-vite preview

# Package for distribution
electron-builder --mac
electron-builder --win
electron-builder --linux
```

There are no test or lint scripts configured.

## Architecture

### Process Model

Three build targets configured in `electron.vite.config.mts`:
- **Main process** (`src/main/index.ts`) — Window management, file I/O, IPC routing, terminal, git
- **Preload** (`src/main/preload-entry.ts`) — contextBridge with whitelisted channels (contextIsolation: true, nodeIntegration: false)
- **Renderer** (`src/renderer/main.ts` → `App.svelte`) — Svelte 5 UI shell, panels, state

Build outputs go to `dist/main/`, `dist/preload/`, `dist/renderer/`.

### Main Process Modules

`appState.ts` is a leaf-module singleton imported by all other main modules — never import project modules into it (circular dependency prevention). The remaining modules are organized by domain:

- `ipcHandlers.ts` — Central IPC message router dispatching to:
  - `fileManager.ts` — File I/O, auto-save (1s debounce), chokidar watcher (3s timestamp guard to prevent sidebar flicker), compiler invocation, AI snapshot ring buffer persisted to `<project>/.vswrite/ai-snapshots/` (configurable max), project-local auto-backup timer (configurable interval), `closeProject()` / `closeProjectInteractive()` for clean teardown. Adds breadcrumbs to `crashReporter` on save / open / close.
  - `importExport.ts` — PDF + DOCX export with chapter-selection modal, Markdown import, Zotero, style templates. `runFilteredExport()` writes a temporary filtered root file (`.vswrite-export-temp.typ`), compiles, and cleans up. DOCX uses `resolveIncludes()` from shared to merge the project before serialization.
  - `projectManager.ts` — Project templates, `openProject()` (folder picker), `openSampleProject()` (resolves `resources/sample-project/` from `process.resourcesPath` in production, copies it to a user-chosen location, runs `git init` + initial version, then opens), `ensureProjectInfrastructure()` (lazy `git init` + `.gitignore` + `.vswrite/` skeleton + initial commit), `handleNewFolder()` and `handleAddAssets()`. Skill-template content lives in `src/shared/skillTemplates.ts`; deploy is per-file (not dir-level) so user customisations to one skill don't block updates to another.
  - `gitManager.ts` — Low-level Git verbs (status/stage/commit/push/pull) plus high-level "Versionen" API: `git:saveVersion`, `git:listVersions`, `git:showVersion` (parses unified diff), `git:restoreVersion`, `git:getRemote`/`setRemote`
  - `projectSearch.ts` — Project-wide find & replace across `.typ` (and optionally `.bib`), regex/case/whole-word, max 1000 hits with truncation flag. Whole-word uses `(?<!\w)…(?!\w)` lookarounds — **NOT** `\b…\b`, because `\b` doesn't fire when the term starts with a non-word char like `@` (citation backlinks would silently return zero hits otherwise). Live in-memory content for the open file is searched alongside disk content. Optional `projectDir` parameter (dual-tauglich) so the same code drives the IPC handler and the MCP `vswrite_search_project` tool.
  - `projectLabels.ts` — Powers the cross-reference picker. Walks every `.typ` file (skipping `.git`, `.vswrite`, `assets`, `sources`, `comments`), pulls `<label>` matches and best-effort captions (heading text, nearest `caption: [...]` in a `#figure(...)`, equation snippet, or text-before-label fallback). Classifies each label by name prefix (`fig|tbl|eq|sec|chap` etc.). Capped at 2000 labels with a truncation flag. Same dual-tauglich pattern as `projectSearch`.
  - `commentManager.ts` — Comments live as `<project>/comments/<id>.md` (sortable id like `2026-04-28-1432-a3f`), one Markdown file per comment with YAML frontmatter (`id`, `file`, `anchor`, `rangeStart/End`, `author`, `date`, `resolved`) + Markdown body. Visible folder, cloud-sync-friendly, never compiled into PDF/DOCX. Reanchoring: exact offset hit → `indexOf` from `rangeHint - 200` → global → `orphaned: true`. Has its own minimal YAML parser (no external dep).
  - `citationSources.ts` — `findSourceForCitation(projectDir, citekey)` looks up `sources/<citekey>*.pdf` (exact match preferred, then suffix variants). Used by both the IPC handler `project:findSourceForCitation` and the MCP `vswrite_find_source_for_citation` tool.
  - `crashReporter.ts` — Local crash reporter. `setupCrashCapture()` registers `uncaughtException` + `unhandledRejection` handlers, starts Electron's native Crashpad, enables `process.setSourceMapsEnabled(true)`. `addBreadcrumb(kind, msg)` feeds a 50-entry ring buffer; `captureMainCrash` / `captureRendererCrash` write plaintext to `<userData>/crash-reports/<timestamp>-<ms>-<rand>.txt` with username scrubbing for `/Users/<x>/`, `/home/<x>/`, `C:\Users\<x>\`. Boot detection compares latest mtime against `.last-shown` marker (uses `Number()` not `parseInt` so the float fraction doesn't get truncated). Rotation at 10 files. Renderer crashes arrive via `crash:report` IPC; the boot dialog is `CrashReportDialog.svelte`, mailto pre-fills `feedback@vswrite.com`.
- `typstCompiler.ts` — Typst → PDF compilation only (SVG mode removed in Session 9 — was blocking the main thread on large docs). Emits `compiledPdf` event with raw buffer.
- `typstPath.ts` — Resolves the typst binary. Production: bundled at `resources/bin/typst-{arch}-{platform}`. Otherwise probes common locations (`/opt/homebrew/bin`, `/usr/local/bin`, `~/.cargo/bin`, …) and falls back to `command -v typst` via `/bin/sh -lc` because macOS GUI apps don't inherit Homebrew PATH.
- `terminalManager.ts` — node-pty wrapper for integrated terminal
- `menuBuilder.ts` — Native menu bar with five top-level menus. **File** (New / Open / Close Project, Save / Save As, Export PDF/DOCX, Import Markdown, Link Zotero, Open Sources Folder, Add Citation Manually), **Edit** (standard roles + Find & Replace `Cmd+F`, **Find in Project** `Cmd+Shift+F`, **Add Comment** `Cmd+Alt+M`, Undo AI Edit), **View** (panel toggles + Focus / Typewriter / **Reading Mode** `Cmd+Alt+R` + zoom roles), **Document** (Settings, Style Templates submenu, Merge / Split, Open as Typst Source, Ensure Bibliography), **Help** (User Guide, Keyboard Shortcuts, Report Issue). Most items send a `vswrite` IPC message that ipcHandlers / messageHandler dispatches.
- `lockManager.ts` — File locking for shared folders (Dropbox, iCloud)
- `persistenceManager.ts` — Two-storage model. Global state via electron-store: window bounds, panel state, license blob (encrypted), recent projects (folder paths, dead entries auto-filtered), backup config. Project-local helpers for `<project>/.vswrite/backups/<timestamp>/`: `saveProjectBackup`, `listProjectBackups`, `loadProjectBackup`, `pruneProjectBackups`, `checkForFileRecovery`. Project-local **preferences** at `<project>/.vswrite/preferences.json` via `getProjectPreferences` / `saveProjectPreferences` — currently holds `{ editorZoom, pdfZoom }`, both clamped to 0.5–2.0 on read and write.
- `licenseManager.ts` — Polar SDK: license activation, validation, offline grace (30 days)
- `mcpSetup.ts` — Auto-discovery of Claude Desktop. `checkClaudeDesktopInstalled()`, `setupMcpServer()` (copies the Bun-compiled MCP binary from the .app's `Resources/mcp/bin/` into `~/Library/Application Support/vswrite/mcp-server/`, then merges a `vswrite` entry into `claude_desktop_config.json` with `env.VSWRITE_LICENSE_KEY` — idempotent, preserves other `mcpServers`, takes timestamped backups, refuses to overwrite invalid JSON), `openClaudeDesktop()`. macOS-only for now. The standalone-binary approach decouples the MCP child from the running app — Claude Desktop can spawn it whether vswrite is running or not, and quitting vswrite never kills the MCP child.

### IPC Communication

Three patterns through the preload bridge (`window.electronAPI`):
- **send** (fire-and-forget): `vswrite`, `terminal:*` channels
- **on** (push from main): `vswrite`, `terminal:data` channels
- **invoke** (request-response): `dialog:*`, `app:*`, `filetree:*`, `includes:*`, `textfile:*`, `git:*`, `project:*`, `export:*`, `persist:*`, `license:*`, `spellcheck:*`, `crash:*` (~70 channels)

Notable channel groups added since the original port:
- `project:open`, `project:openSample` (copies bundled sample to user-chosen path + git-init + initial version), `project:close`, `project:newFolder`, `project:addAssets`, `project:listBackups`, `project:loadBackup`, `project:applyBackup`, `project:getBackupConfig`, `project:setBackupConfig`, `project:openBackupFolder`, `project:showInFinder`, `project:findSourceForCitation`, `project:getInfo`, `project:getPreferences`, `project:setPreferences` (per-project zoom levels in `<project>/.vswrite/preferences.json`)
- `project:search`, `project:replaceAll` — project-wide find/replace, used by `ProjectSearchPanel` and the backlinks triggers
- `project:listLabels` — returns all `<label>`s in the project for the cross-reference picker
- `project:findSourceForCitation` — looks up `sources/<citekey>*.pdf` for the citation hover card
- `comments:list`, `comments:create`, `comments:update`, `comments:delete` — comment CRUD on `<project>/comments/`
- `git:saveVersion`, `git:listVersions`, `git:showVersion`, `git:restoreVersion`, `git:ensureRepo`, `git:getRemote`, `git:setRemote`
- `export:getSections`, `export:run`
- `crash:report` (renderer → main), `crash:getLatest`, `crash:markShown`, `crash:deleteAll`, `crash:openFolder`, `crash:copyToClipboard`, `crash:openMail` — local crash reporter
- `mcp:checkClaudeDesktop`, `mcp:setup`, `mcp:openClaude`, `mcp:getSetupStatus`, `mcp:skipSetup` — Claude-Desktop auto-discover wizard (`McpSetupWizard.svelte`); `MCP_SETUP_VERSION` in `mcpSetup.ts` is bumped whenever the binary or config schema changes, electron-store tracks the last version the user ran setup for so the wizard re-triggers on bump

Message types are defined in `src/editor/lib/messages.ts`. The IPC adapter (`src/editor/lib/ipcAdapter.ts`) auto-detects Electron vs VS Code context, so editor code works in both environments.

### Renderer State

`src/renderer/appState.svelte.ts` uses Svelte 5 runes (`$state`, `$derived`, `$effect`) with sections: editor state, UI state (incl. `showProjectSearch`, `readingMode`), panel state (sidebar tab can be `'files' | 'outline' | 'includes' | 'git' | 'comments' | 'design'`), preview state (PDF only — `pdfData`/`error`/`compiling`), tab state, context menu, new project dialog, export dialog state, **`projectSearchPreset`** (consumed-once seed for the next ProjectSearchPanel mount; see "Cross-component triggers" below).

`App.svelte` derives **`wordStats`** (`{ words, minutes }`) from the editor JSON, walking the tree and skipping `typstRawBlock` / `codeBlock` / `pagebreak` so code doesn't inflate the count. Tracked reactively via `editorVersion.value`. Displayed in the status bar as `1,247 words · 5 min read` (200 wpm).

Key components in `src/renderer/components/`:
- `Sidebar.svelte` — file tree with inline "New Folder" input + "Add Asset" picker, empty folders visible, `▾`/`▸` chevrons
- `OutlinePanel.svelte` — heading hierarchy navigation; each row has a hover-only `↪` button that dispatches `vswrite:find-backlinks` for the heading title. Rows are also `draggable` for reordering: dropping a heading executes a single PM transaction that moves the entire heading-block (heading + everything up to the next heading of equal-or-higher rank) via `doc.slice(from, to)` → `tr.delete` → `tr.replace`. Single-file only — cross-file reorder lives in the Chapters tab.
- `ProjectPanel.svelte` — replaces the old `GitPanel.svelte`. Contains the project header, "Save Version" card, change list with checkboxes, always-visible history, auto-backup status footer, collapsible "Advanced" section for cloud sync
- `CommentsPanel.svelte` — fifth sidebar tab. Lists comments for current file or whole project, body textarea with 400 ms debounced auto-save, resolve/delete actions, anchor-click jumps editor + flashes the highlight. Pushes decorations only on comment-list changes (NOT on `editorVersion` — that caused an infinite loop; the plugin handles `tr.docChanged` itself)
- `ProjectSearchPanel.svelte` — slide-in for `Cmd+Shift+F`. Live-debounced search with options Aa/W/.*/.bib, results grouped by file, click jumps + scrolls + briefly highlights. Reads `projectSearchPreset` on mount and clears it (consume-once)
- `VersionDetail.svelte` — modal for one history entry with source-text diff (red/green lines) and "Restore this version"
- `BackupListDialog.svelte` — auto-backup browser with collapsible settings (interval, max count, max AI snapshots)
- `ExportDialog.svelte` — format picker (PDF/DOCX) with chapter checkboxes; only opens for multi-chapter projects, single-file exports skip straight to the save dialog
- `CitationHoverCard.svelte` — popover shown after 350 ms hover on a `@citekey` badge. Reads bib metadata from `getCitationEntries()`, calls `project:findSourceForCitation` to detect a `sources/<citekey>*.pdf`, and exposes an "Open PDF" button that opens the source as a regular PdfFileViewer tab. Owns its own close-with-grace-period (250 ms) so the user can move from badge to card without the card vanishing.
- `ReferencePicker.svelte` — modal triggered by `/Reference`, `Edit → Insert Reference…`, or `Cmd+Alt+L`. Lists all `<label>`s grouped by type with caption preview and `relPath:line`. Keyboard nav (↑↓ Enter Esc), filter input, type-tabs. Picker calls back via `onPick`; App.svelte inserts a `reference` node at the cursor.
- `CrashReportDialog.svelte` — boot dialog mounted by App.svelte's onMount when `crash:getLatest` returns an unshown report. Two-view modal (intro → detail), buttons: Copy / Mail / Open folder / Discard / Close. Closing in any path runs `crash:markShown` so the same report doesn't reappear next boot.
- `StartScreen.svelte` — visible when no project is open. Three action cards (`New Project` / `Open Sample Project` / `Open Project`) plus a recent-projects list. The Sample button invokes `project:openSample` which copies `resources/sample-project/` to the user's chosen location.

`messageHandler.ts` listens for backend events including `projectClosed` (resets all editor state), `showExportDialog` (opens ExportDialog), `backupCreated` (refreshes the auto-backup status line), `aiSnapshotCount`. It also handles native-menu-driven renderer state changes: `showSearch`, `showProjectSearch`, `showShortcuts`, `toggleFocusMode`, `toggleTypewriterMode`, `toggleReadingMode`, `addComment` (re-dispatches as `vswrite:add-comment` window event).

### Editor (`src/editor/`)

TipTap-based rich text editor with ~19 custom Typst node extensions (`typst*.ts`). Key modules:
- `serializer.ts` — TipTap JSON → Typst source
- `deserializer.ts` — Typst source → TipTap JSON. Handles `#align(spec)[…]` blocks (incl. combined alignments like `center + horizon`), unwraps nested `#text(size, weight)[…]`, recognises `#datetime.today().display(…)`. Multi-line list items (`+ item\n  cont.`) are joined. Inline `#footnote[…]` is parsed into a footnote node.
- `reconciler.ts` — Incremental document updates
- `typstFootnote.ts` — Inline atomic node `footnote` with click-to-edit popup. Exports `insertFootnoteWithEditor(editor)` — inserts an empty footnote and synthesises a click on the freshly mounted DOM node so the popup auto-opens. Used by both the toolbar Fn button and the `/Footnote` slash command.
- `typstCitation.ts` — Inline atomic node `citation` (`@citekey` badge). `contextmenu` handler dispatches `vswrite:find-backlinks` with `@<citekey>` (whole-word) so right-click finds every usage in the project. `mouseenter` starts a 350 ms dwell timer that dispatches `vswrite:citation-hover` with `{ citekey, rect }`; `mouseleave` dispatches `vswrite:citation-leave`. The hover card (App.svelte) decides whether to mount.
- `typstReference.ts` — Inline atomic node `reference` (`@label` cross-ref badge). Visually distinct (orange ↳ pill) from citation badges. Serializes to `@label` exactly like a citation; the deserializer's `isReferenceLabel()` heuristic decides which kind a parsed `@name` is — labels with a colon OR matching a known prefix (`fig|tbl|eq|sec|chap|app|thm|lem|def|cor|prop|algo|lst` and full forms) become reference nodes; bare slugs stay citations. `@` is **not** a UI trigger for references — the picker is the only insertion path.
- `commentDecorations.ts` — TipTap extension that renders gold-yellow inline decorations for active comment anchors **without modifying the document**. `setCommentMarks(editor, marks)` pushes a new mark list via plugin-meta transaction. The plugin's `apply()` rebuilds decorations on `tr.docChanged` itself — DO NOT trigger `setCommentMarks` from a `$effect` that tracks `editorVersion`, that loops infinitely (transaction → onTransaction → editorVersion++ → effect → transaction).
- Svelte components: `Toolbar.svelte` (Fn / Cm buttons + reading-mode 𝓡 toggle), `SettingsPanel.svelte`, `SearchReplace.svelte`, `QuickSettings.svelte`, `ShortcutCheatsheet.svelte`, `WelcomeScreen.svelte`. (The old `CommandHub.svelte` was retired in Session 11 — its actions live in the native menu bar and slash commands now.)

### Shared Code (`src/shared/`)

Code used by both main and renderer: settings parser, bib parser, DOCX serializer, style/project templates, document merge/split, markdown importer. Also `skillTemplates.ts` — five Claude-Code-skill string constants (`TYPST_SKILL`, `VSWRITE_SKILL`, `RESEARCH_SKILL`, `WRITING_STYLE_SKILL`, `DESIGN_SKILL`) with tilde-fenced code blocks (avoids backtick escapes in TS template literals); `projectManager.ensureClaudeSkills` deploys these to `<project>/.claude/skills/<name>/SKILL.md` per-file. The MCP server (`mcp/server.ts`) exposes the same skills as prompts (`typst-reference`, `vswrite-conventions`, `research-workflow`, `writing-style`, `design-conventions`) by reading them out of the project's `.claude/skills/<name>/SKILL.md`. Import via `@shared` alias.

Configured in electron.vite.config.mts: `@shared` → `src/shared/`, `@editor` → `src/editor/`.

## Key Patterns

- **Preload whitelist:** any new IPC channel must be added to the allowed lists in `preload-entry.ts`. The `SEND_CHANNELS` list is small (terminal + `vswrite` event channel); most new work goes into `INVOKE_CHANNELS`.
- **Typst compilation** always targets the root file (for multi-chapter support) and outputs PDF only. Never call `'typst'` directly — always use `getTypstPath()` so bundled-vs-system resolution works. For the args list, use `buildTypstCompileArgs(['<input>', '<output>'])` from `typstPath.ts`; it prepends `--package-path` so the bundled Typst packages (cetz, fletcher, showybox, codly, ...) resolve offline. The MCP server has its own `typstCompileArgs()` helper that reads `TYPST_PACKAGE_PATH` from env (set by the MCP setup wizard).
- **Bundled Typst packages:** 24 packages live under `resources/typst-packages/preview/<name>/<version>/` (13 user-facing + 11 transitive deps). `scripts/fetch-typst-packages.mjs` pulls them from `packages.typst.org`. `scripts/audit-bundled-deps.mjs` runs as part of `package:*` and fails the build if any LICENSE classifies as GPL/AGPL or doesn't match its `typst.toml` declaration. The audit emits `THIRD_PARTY_LICENSES.md` at the repo root and `resources/typst-packages/bundle-licenses.json` for the in-app Acknowledgments dialog. Bundled list lives in the script's `PACKAGES` array — that's the single source of truth.
- **pdfjs `ArrayBuffer` is single-use:** `pdfjsLib.getDocument({ data })` transfers the buffer to the worker (zero-copy optimization), leaving it detached in the main thread. Re-calling `getDocument` with the same `data` throws `DataCloneError: ArrayBuffer is already detached`. When the document needs to update (zoom, scale changes), keep the loaded `currentPdf` and re-call `page.getViewport({ scale })` + `renderPage` instead of recreating the document.
- **Document zoom** is two independent levels: editor uses CSS `zoom: var(--editor-zoom)` on `.editor` (Chromium reflows the layout correctly, ProseMirror selection coordinates stay accurate — unlike `transform: scale` which breaks them); PDF uses pdfjs viewport scale `BASE_SCALE * pdfZoom` plus a proportional placeholder width so horizontal scroll kicks in above 100 %. Both are stored per-project in `.vswrite/preferences.json` and shared between the live preview (`PdfPreviewPanel`) and source-PDF tabs (`PdfFileViewer`).
- **External file changes** are detected via chokidar; the watcher uses a 3-second timestamp guard (`lastSaveTimestamp`) to ignore self-triggered events. The watcher also ignores `**/.vswrite/**` so backups never trigger refresh loops.
- **Five independent project-local persistence layers** — keep them conceptually separate:
  - **Versions** (Git): user-triggered "Save Version" → `git commit`. Lives in `<project>/.git/`. Use the high-level handlers (`git:saveVersion`, `git:listVersions`, `git:restoreVersion`); the low-level verbs are kept for the "Advanced" cloud-sync UI only.
  - **Auto-backups**: timer-driven multi-file snapshots in `<project>/.vswrite/backups/<timestamp>/`. Each snapshot is a flat folder of files plus a `.meta.json`. On open, `checkForFileRecovery()` offers to restore if the latest backup is newer than the disk file.
  - **AI-edit snapshots**: ring buffer in `<project>/.vswrite/ai-snapshots/`, persisted as JSON per entry, restored into memory on project open. Used by "Undo AI Edit" — never confuse with versions.
  - **Preferences**: `<project>/.vswrite/preferences.json` holds per-project UI knobs (currently `editorZoom`, `pdfZoom`). Read/written via `getProjectPreferences` / `saveProjectPreferences`. Loaded on first `currentFile` event after open (cached by projectDir to avoid re-loads on file switches inside the same project); reset to defaults on `projectClosed`. Debounced save on change. When adding new per-project UI settings, extend this file rather than electron-store.
  - **Style** (Design-Editor — Sessions 21–23.2): `<project>/.vswrite/style.json` holds the typed "design tokens" via `getProjectStyle` / `saveProjectStyle` / `hasProjectStyle` (`persistenceManager.ts`). Schema covers colors (5 semantic slots), fonts (body / heading / code), scale (base / leading / paragraphSpacing / firstLineIndent), layout (paper / orientation / margin / columns / pageNumbering / pageHeader / pageFooter / pageFill), headings h1–h6 (size / weight / color-slot / marginTop) + numbering, elements (blockquote / codeBlock / figure with `creditSeparator` + `creditLabel` for photographer credits / table), and `custom.preamble` (free-form Typst escape hatch). Schema + sanitizer in `src/shared/styleTypes.ts`. `style:save` regenerates `<project>/style.typ` via `generateStyleTypst()` (`src/shared/styleParser.ts`) and ensures the root file has `#import "style.typ": *` + `#show: apply-style` at the top (legacy `#include "style.typ"` is auto-migrated by `ensureStyleInclude`). The fenced custom-code block is round-tripped via `extractCustomBlock()` — manual edits to that section survive regeneration. The generated `style.typ` exports four module-level values besides the `apply-style` function: `style-colors` (palette dict), `style-fonts` (body/heading/code dict), `figure-caption-credit(caption, credit)` (helper for photographer captions, uses the configured `creditSeparator` + `creditLabel`), and the running-head helpers `chapter-name()` / `section-name()` — header/footer markup strings can use `{chapter}` / `{section}` placeholders that the generator substitutes with these calls (`substituteRunningHeadPlaceholders` in `styleParser.ts`). **Presets** live in three places: `palettePresets.ts` (8 color-only), `themePresets.ts` (6 full ProjectStyle snapshots — Classic Academic, Modern Tech, Editorial Magazine, Minimal, Marketing Brochure, Thesis), `layoutPresets.ts` (7 layout-only swaps — A4 portrait/landscape, 2-col magazine, 3-col newsletter, A5 booklet, A2 poster, Magazine Editorial with per-chapter running head). Theme apply preserves `custom.preamble`; layout apply only swaps `layout.*` and optionally `scale.base`. The Document Settings dialog is trimmed to `lang` + `bibliographyStyle`; QuickSettings writes `scale.base` / `scale.leading` into style.json. **MCP design tools** (Session 22 — Phase C, 11 total): `vswrite_get_style` / `vswrite_update_style` (deep-merge with sanitizer) / `vswrite_list_fonts` / `vswrite_apply_palette` / `vswrite_list_layouts` (7) / `vswrite_apply_layout` / `vswrite_list_design_elements` / `vswrite_insert_design_element` (**19 parametric snippets** as of Session 23.1 — Banner / Sidebar / Pull-Quote / Callout / Hero / Divider plus Round-4 additions Drop-Cap / Divider-Asterisks / Divider-Ornament / Pull-Quote-Display / Pull-Quote-Block / Article-Opener / Section-Opener / Gallery-2up / Gallery-3up / Magazine-Cover plus Round-5 additions Gallery-Asymmetric / Image-Overlay / Stats-Box / Photo-Caption-Wrap — all defined in `designElements.ts`, each references `style-colors.*` and `style-fonts.*` so they re-theme automatically) / `vswrite_generate_layout` (NL intent → theme + layout + optional hero). `vswrite_list_styles` and `vswrite_apply_style` are migrated to THEME_PRESETS; the legacy preamble-string `styleTemplates.ts` is retained only as a stub for callers that haven't migrated. Fifth project skill `DESIGN_SKILL` (color theory / typography pairing / layout patterns / running-heads / modern aesthetics / anti-patterns) deployed via `ensureClaudeSkills` and exposed as MCP prompt `design-conventions`.
- **`resolveIncludes()` from `src/shared/mergeDocument.ts`** is used for DOCX export (typst itself follows includes natively for PDF). It produces a merged source with comment markers separating each chapter — note the **blank line after the marker** is essential, otherwise the marker glues to the chapter's H1 and the deserializer drops the heading as a config block.
- **Style template application is blocked outside the root file** — applying a style preamble to a chapter file silently corrupts it. `applyStyleTemplate()` checks `findRootFile(currentFilePath) === currentFilePath` and shows a native dialog otherwise.
- **Project lifecycle:** `closeProject()` (clean teardown — releases lock, stops watcher, disposes compiler, clears timers, sends `projectClosed` to renderer) vs. `closeProjectInteractive()` (prompts to save first if dirty). `openProject()` calls the interactive close before opening a new one. Always go through these — never reset `appState` fields directly.
- **Security:** all file read/write IPC handlers validate paths with `isPathWithin()` from `pathSecurity.ts` (realpath-based, symlink-safe). Sandbox is enabled; preload uses contextIsolation. The asset protocol (`vswrite-asset://`) and the MCP server's file tools have their own path validation.
- **Action-discovery split:** native menu bar = project / document / file actions and rare dialogs. Slash commands (`/`) = in-text content insertions (image, table, math, citation, divider, page break, footnote …). Toolbar = frequent inline format buttons (B/I/U/S, headings, lists, code, link, Fn/Cm) plus the right-side mode toggles (Quick / Typewriter / Reading 𝓡 / Focus). When adding a new action, decide which surface it belongs to and pick exactly one — don't duplicate.
- **Cross-component triggers via `window` Custom Events:** UI surfaces dispatch DOM `CustomEvent`s on `window` and `App.svelte` listens at the top. Current events:
  - `vswrite:add-comment` — Toolbar Cm button / menu / `Cmd+Alt+M` → `addCommentFromSelection()`
  - `vswrite:comment-click` — comment-decoration click → `CommentsPanel` scrolls panel to entry
  - `vswrite:comment-created` — after `comments:create` IPC → `CommentsPanel` refreshes + focuses new entry
  - `vswrite:find-backlinks` — OutlinePanel hover-arrow / Citation right-click → seeds `projectSearchPreset` + opens ProjectSearchPanel
  - `vswrite:project-search-jump` — match-click in ProjectSearchPanel → editor scrolls to first occurrence of match text
  - `vswrite:citation-hover` / `vswrite:citation-leave` — TypstCitation node-view → App.svelte mounts/unmounts CitationHoverCard. The card itself also listens to both events to manage its grace-period close.
  - `vswrite:open-reference-picker` — `/Reference` slash command and the `showReferencePicker` IPC (from menu / `Cmd+Alt+L`) → App.svelte mounts ReferencePicker.
  Pattern works because there's only one App-level listener — keep it that way; don't dispatch the same event from two listeners.
- **`src/cli/` and `src/mcp/`** exist from the VS Code extension; CLI is unused. The MCP server runs as a standalone Node.js process. As of Session 23.2 it exposes 52 typed tools across 13 categories (Project / Document / Settings / **Design** / Chapters / Bibliography / Cross-Refs+Footnotes / Comments / Versions / Discovery / Export / Import+Assets / Git low-level) plus five skill prompts (`typst-reference`, `vswrite-conventions`, `research-workflow`, `writing-style`, `design-conventions`). `vswrite_compile` is a verifier — PDF temp-file then unlinked; `vswrite_export_pdf` and `vswrite_export_docx` own artefact writing and route through `resolveInsideProject`. Anchor-based tools (`add_comment` / `insert_reference` / `add_footnote` / `add_image` / `insert_design_element`) take an `afterText`/`anchor` plus an optional 1-based `occurrence` parameter so the agent never computes offsets. **Skill prompts are read from disk per-project** (`<project>/.claude/skills/<slug>/SKILL.md`) — the binary does NOT embed skill content, so a skillTemplates change only needs the user to delete the stale SKILL.md on existing projects (new projects pick up the change automatically via `ensureClaudeSkills`). Full reference: [documentation/mcp-server.md](documentation/mcp-server.md).
- **MCP server packaging (Session 18):** the MCP server ships as a **Bun-compiled standalone binary** (~64 MB) under `dist/mcp/bin/vswrite-mcp-<triple>`, built via `scripts/build-mcp-binary.mjs` (host arch by default, `--all` for arm64 + x86). Lives in the .app at `Contents/Resources/mcp/bin/` via `extraResources`. The Setup-Wizard (`McpSetupWizard.svelte` / `mcpSetup.ts`) copies the binary out to `~/Library/Application Support/vswrite/mcp-server/vswrite-mcp` on user opt-in. **Decoupled from the running app** — quitting vswrite does not affect the MCP child Claude Desktop already spawned, and launch order is irrelevant. The user's Pro license key is pulled from electron-store and written into the Claude config as `env.VSWRITE_LICENSE_KEY` so the server can self-validate on startup. Hardened Runtime needs JIT entitlements (`build/entitlements.mac.mcp.plist`) — `scripts/afterPack-sign-mcp.mjs` re-signs the binary with these after electron-builder's default sign pass so the main app keeps stricter entitlements. The legacy `dist/mcp/server.mjs` (esbuild output) still exists for users who want to run the server under their own Node, but the wizard no longer uses it.
