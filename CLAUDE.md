# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

vswrite-desktop is a standalone Electron desktop app for WYSIWYG editing of Typst documents, ported from the vswrite VS Code extension. Tech stack: Electron 41, electron-vite 5, Svelte 5 (runes), TipTap/ProseMirror 3, simple-git, pdf.js. Typst CLI is bundled with the app (no user installation needed).

The app is **project-first**: every file lives inside a project folder. Each project is self-contained — the Git history (`.git/`), auto-backups (`.penwright/backups/`), AI-edit snapshots (`.penwright/ai-snapshots/`), and per-project UI preferences (`.penwright/preferences.json`) all live inside the project, so copying or moving the folder takes the full state with it. The app starts at the Start Screen and never auto-reopens a project.

## Naming Convention (Penwright — read before introducing new identifiers)

The product was renamed **vswrite → Penwright**. **Canonical name is `Penwright` (prose / UI) and `penwright` (identifiers).** All new code, tools, UI text, IPC channels, events, CSS classes, log tags, protocols, and the project state folder (`.penwright/`) MUST use `penwright`/`Penwright`. There should be **no new `vswrite`** anywhere. License keys are `pw_LIC…`; the support email is `feedback@penwright.online`.

**Intentional `vswrite` holdouts** (do NOT "fix" these — they are deliberate):
- **`vswrite-desktop`** — the git repo + working-directory name. Renaming it would break clones, remotes, and absolute paths. Stays until/unless the repo itself is renamed.
- **`.vswrite` literals in `projectManager.migrateLegacyProjectDir`** — the one-shot `.vswrite/` → `.penwright/` migration must reference the *old* folder name to find and rename it. Intentional.
- **Historical docs** — `documentation/done/**`, `documentation/handover.md`, and the changelog `documentation/project_status.md` are kept as accurate history (e.g. "ported from the vswrite VS Code extension", session entries describing the rename). Not rewritten.

The electron-store filename was renamed `vswrite-settings` → **`penwright-settings`** — no migration, so the prior global state (recent projects, license blob, trial-start date) resets once on first launch.

**Web domain:** canonical is **`penwright.online`** (Website button, manifest homepage/support, support email `feedback@penwright.online`). The **User Guide ships in-app** — `HandbookViewer.svelte` renders the bundled handbook (`documentation/handbuch.md` for German UI, `handbook.md` otherwise); there is no external docs site. `penwright.online` still needs to be registered before the website/pricing links resolve.

## Architecture

### Process Model

Three build targets configured in `electron.vite.config.mts`:
- **Main process** (`src/main/index.ts`) — Window management, file I/O, IPC routing, git
- **Preload** (`src/main/preload-entry.ts`) — contextBridge with whitelisted channels (contextIsolation: true, nodeIntegration: false)
- **Renderer** (`src/renderer/main.ts` → `App.svelte`) — Svelte 5 UI shell, panels, state

Build outputs go to `dist/main/`, `dist/preload/`, `dist/renderer/`.

### Main Process Modules

`appState.ts` is a leaf-module singleton imported by all other main modules — never import project modules into it (circular dependency prevention). The remaining modules are organized by domain:

- `ipcHandlers.ts` — Central IPC message router dispatching to:
  - `fileManager.ts` — File I/O, auto-save (1s debounce), chokidar watcher (3s timestamp guard to prevent sidebar flicker), compiler invocation, AI snapshot ring buffer persisted to `<project>/.penwright/ai-snapshots/` (configurable max), project-local auto-backup timer (configurable interval), `closeProject()` / `closeProjectInteractive()` for clean teardown. Adds breadcrumbs to `crashReporter` on save / open / close.
  - `importExport.ts` — PDF + DOCX export with chapter-selection modal, Markdown import, Zotero, style templates. `runFilteredExport()` writes a temporary filtered root file (`.penwright-export-temp.typ`), compiles, and cleans up. DOCX uses `resolveIncludes()` from shared to merge the project before serialization, then passes the project style **and** a `renderTypstSnippet` callback (`createTypstSnippetRenderer`) into `serializeDocx`. As of Session 25 the DOCX serializer (`src/shared/docxSerializer.ts`) no longer dumps `typstRawBlock`s as monospace — it classifies + renders them (`#figure` → image/table + numbered caption, display-math + SVG → rasterised via the injected callback, `#quote` → Quote, gentle-clues callouts → accent box, prose-with-inline → a real paragraph; pure layout/design code is skipped). The math/SVG renderer is injected (not imported) so `shared/` stays dependency-free; the MCP server wires its own (`createMcpSnippetRenderer`).
  - `projectManager.ts` — Project templates, `openProject()` (folder picker), `openSampleProject()` (resolves `resources/sample-project/` from `process.resourcesPath` in production, copies it to a user-chosen location, runs `git init` + initial version, then opens), `ensureProjectInfrastructure()` (lazy `git init` + `.gitignore` + `.penwright/` skeleton + initial commit), `handleNewFolder()` and `handleAddAssets()`. Skill-template content lives in `src/shared/skillTemplates.ts`; deploy is per-file (not dir-level) so user customisations to one skill don't block updates to another. Project templates are defined in `src/shared/projectTemplates.ts` (6 templates: document / thesis / paper / letter / book / **magazine**). The `magazine` template is designed for the [ai-magazine-designer](https://github.com/renejes/ai-magazine-designer) Slow-Media pipeline — ships `chapters/_cover-macro.typ` (stable `magazine-cover` macro definition) + `chapters/00-cover.typ` (macro call, rewritten by the cover-designer skill per issue) + editorial + TOC chapter slots. No `.penwright/style.json` shipped; the typst-architekt skill calls `penwright_generate_layout("magazine")` or `penwright_update_style` on demand if it wants Design-Editor integration.
  - `gitManager.ts` — Low-level Git verbs (status/stage/commit/push/pull) plus high-level "Versionen" API: `git:saveVersion`, `git:listVersions`, `git:showVersion` (parses unified diff), `git:restoreVersion`, `git:getRemote`/`setRemote`
  - `projectSearch.ts` — Project-wide find & replace across `.typ` (and optionally `.bib`), regex/case/whole-word, max 1000 hits with truncation flag. Whole-word uses `(?<!\w)…(?!\w)` lookarounds — **NOT** `\b…\b`, because `\b` doesn't fire when the term starts with a non-word char like `@` (citation backlinks would silently return zero hits otherwise). Live in-memory content for the open file is searched alongside disk content. Optional `projectDir` parameter (dual-tauglich) so the same code drives the IPC handler and the MCP `penwright_search_project` tool.
  - `projectLabels.ts` — Powers the cross-reference picker. Walks every `.typ` file (skipping `.git`, `.penwright`, `assets`, `sources`, `comments`), pulls `<label>` matches and best-effort captions (heading text, nearest `caption: [...]` in a `#figure(...)`, equation snippet, or text-before-label fallback). Classifies each label by name prefix (`fig|tbl|eq|sec|chap` etc.). Capped at 2000 labels with a truncation flag. Same dual-tauglich pattern as `projectSearch`.
  - `commentManager.ts` — Comments live as `<project>/comments/<id>.md` (sortable id like `2026-04-28-1432-a3f`), one Markdown file per comment with YAML frontmatter (`id`, `file`, `anchor`, `rangeStart/End`, `author`, `date`, `resolved`) + Markdown body. Visible folder, cloud-sync-friendly, never compiled into PDF/DOCX. Reanchoring: exact offset hit → `indexOf` from `rangeHint - 200` → global → `orphaned: true`. Has its own minimal YAML parser (no external dep).
  - `citationSources.ts` — `findSourceForCitation(projectDir, citekey)` looks up `sources/<citekey>*.pdf` (exact match preferred, then suffix variants). Used by both the IPC handler `project:findSourceForCitation` and the MCP `penwright_find_source_for_citation` tool.
  - `crashReporter.ts` — Local crash reporter. `setupCrashCapture()` registers `uncaughtException` + `unhandledRejection` handlers, starts Electron's native Crashpad, enables `process.setSourceMapsEnabled(true)`. `addBreadcrumb(kind, msg)` feeds a 50-entry ring buffer; `captureMainCrash` / `captureRendererCrash` write plaintext to `<userData>/crash-reports/<timestamp>-<ms>-<rand>.txt` with username scrubbing for `/Users/<x>/`, `/home/<x>/`, `C:\Users\<x>\`. Boot detection compares latest mtime against `.last-shown` marker (uses `Number()` not `parseInt` so the float fraction doesn't get truncated). Rotation at 10 files. Renderer crashes arrive via `crash:report` IPC; the boot dialog is `CrashReportDialog.svelte`, mailto pre-fills `feedback@penwright.online`.
- `typstCompiler.ts` — Typst → PDF compilation only (SVG mode removed in Session 9 — was blocking the main thread on large docs). Emits `compiledPdf` event with raw buffer.
- `typstPath.ts` — Resolves the typst binary. Production: bundled at `resources/bin/typst-{arch}-{platform}`. Otherwise probes common locations (`/opt/homebrew/bin`, `/usr/local/bin`, `~/.cargo/bin`, …) and falls back to `command -v typst` via `/bin/sh -lc` because macOS GUI apps don't inherit Homebrew PATH.
- `menuBuilder.ts` — Native menu bar with five top-level menus. **File** (New / Open / Close Project, Save / Save As, Export PDF/DOCX, Import Markdown, Link Zotero, Open Sources Folder, Add Citation Manually), **Edit** (standard roles + Find & Replace `Cmd+F`, **Find in Project** `Cmd+Shift+F`, **Add Comment** `Cmd+Alt+M`, Undo AI Edit), **View** (panel toggles + zoom roles), **Document** (Settings, Style Templates submenu, Merge / Split, Open as Typst Source, Ensure Bibliography), **Help** (User Guide, Keyboard Shortcuts, Report Issue). Most items send a `Penwright` IPC message that ipcHandlers / messageHandler dispatches.
- `lockManager.ts` — File locking for shared folders (Dropbox, iCloud)
- `persistenceManager.ts` — Two-storage model. Global state via electron-store: window bounds, panel state, license blob (encrypted), recent projects (folder paths, dead entries auto-filtered), backup config. Project-local helpers for `<project>/.penwright/backups/<timestamp>/`: `saveProjectBackup`, `listProjectBackups`, `loadProjectBackup`, `pruneProjectBackups`, `checkForFileRecovery`. Project-local **preferences** at `<project>/.penwright/preferences.json` via `getProjectPreferences` / `saveProjectPreferences` — currently holds `{ editorZoom, pdfZoom }`, both clamped to 0.5–2.0 on read and write.
- `licenseManager.ts` — Polar SDK: license activation, validation, offline grace (30 days)
- `mcpSetup.ts` — Auto-discovery of Claude Desktop. `checkClaudeDesktopInstalled()`, `setupMcpServer()` (copies the Bun-compiled MCP binary from the .app's `Resources/mcp/bin/` into `~/Library/Application Support/Penwright/mcp-server/`, then merges a `Penwright` entry into `claude_desktop_config.json` with `env.PENWRIGHT_LICENSE_KEY` — idempotent, preserves other `mcpServers`, takes timestamped backups, refuses to overwrite invalid JSON), `openClaudeDesktop()`. **Platform branches** are abstracted via `isMcpSetupSupported()` (darwin + win32; Linux excluded — no Claude Desktop), `platformBinary()` (triple+ext), `getInstalledBinaryPath()` / `getClaudeConfigPath()` / `claudeAppCandidates()` (per-OS paths: macOS `~/Library/Application Support/…`; Windows `%APPDATA%\Claude`, `%APPDATA%\Penwright`, `%LOCALAPPDATA%\…\Claude.exe`). **macOS is tested; Windows is wired but needs real-device verification.** The standalone-binary approach decouples the MCP child from the running app — Claude Desktop can spawn it whether Penwright is running or not, and quitting Penwright never kills the MCP child.

### IPC Communication

Three patterns through the preload bridge (`window.electronAPI`):
- **send** (fire-and-forget): `Penwright` channel
- **on** (push from main): `Penwright` channel
- **invoke** (request-response): `dialog:*`, `app:*`, `filetree:*`, `includes:*`, `textfile:*`, `git:*`, `project:*`, `export:*`, `persist:*`, `license:*`, `spellcheck:*`, `crash:*` (~70 channels)

Notable channel groups added since the original port:
- `project:open`, `project:openSample` (copies bundled sample to user-chosen path + git-init + initial version), `project:close`, `project:newFolder`, `project:addAssets`, `project:listBackups`, `project:loadBackup`, `project:applyBackup`, `project:getBackupConfig`, `project:setBackupConfig`, `project:openBackupFolder`, `project:showInFinder`, `project:findSourceForCitation`, `project:getInfo`, `project:getPreferences`, `project:setPreferences` (per-project zoom levels in `<project>/.penwright/preferences.json`)
- `project:search`, `project:replaceAll` — project-wide find/replace, used by `ProjectSearchPanel` and the backlinks triggers
- `project:listLabels` — returns all `<label>`s in the project for the cross-reference picker
- `project:findSourceForCitation` — looks up `sources/<citekey>*.pdf` for the citation hover card
- `comments:list`, `comments:create`, `comments:update`, `comments:delete` — comment CRUD on `<project>/comments/`
- `selection:pin`, `selection:get`, `selection:clear` — the "Design after writing" pin (`<project>/.penwright/selection.json`); the renderer passes the selection anchor, main attaches the design snapshot
- `git:saveVersion`, `git:listVersions`, `git:showVersion`, `git:restoreVersion`, `git:ensureRepo`, `git:getRemote`, `git:setRemote`
- `export:getSections`, `export:run`
- `crash:report` (renderer → main), `crash:getLatest`, `crash:markShown`, `crash:deleteAll`, `crash:openFolder`, `crash:copyToClipboard`, `crash:openMail` — local crash reporter
- `mcp:checkClaudeDesktop`, `mcp:setup`, `mcp:openClaude`, `mcp:getSetupStatus`, `mcp:skipSetup` — Claude-Desktop auto-discover wizard (`McpSetupWizard.svelte`); `MCP_SETUP_VERSION` in `mcpSetup.ts` is bumped whenever the binary or config schema changes, electron-store tracks the last version the user ran setup for so the wizard re-triggers on bump

Message types are defined in `src/editor/lib/messages.ts`. The IPC adapter (`src/editor/lib/ipcAdapter.ts`) auto-detects Electron vs VS Code context, so editor code works in both environments.

### Renderer State

`src/renderer/appState.svelte.ts` uses Svelte 5 runes (`$state`, `$derived`, `$effect`) with sections: editor state, UI state (incl. `showProjectSearch`, `readingMode`), panel state (sidebar tab can be `'files' | 'outline' | 'includes' | 'git' | 'comments' | 'design'`), preview state (PDF only — `pdfData`/`error`/`compiling`), tab state, context menu, new project dialog, export dialog state, **`projectSearchPreset`** (consumed-once seed for the next ProjectSearchPanel mount; see "Cross-component triggers" below).

`App.svelte` derives **`wordStats`** (`{ words, minutes }`) from the editor JSON, walking the tree and skipping `typstRawBlock` / `codeBlock` / `pagebreak` so code doesn't inflate the count. Tracked reactively via `editorVersion.value`. Displayed in the status bar as `1,247 words · 5 min read` (200 wpm).

Key components in `src/renderer/components/`:
- `Sidebar.svelte` — file tree with inline "New Folder" input + "Add Asset" picker, empty folders visible, `▾`/`▸` chevrons
- `OutlinePanel.svelte` — heading hierarchy navigation; each row has a hover-only `↪` button that dispatches `penwright:find-backlinks` for the heading title. Rows are also `draggable` for reordering: dropping a heading executes a single PM transaction that moves the entire heading-block (heading + everything up to the next heading of equal-or-higher rank) via `doc.slice(from, to)` → `tr.delete` → `tr.replace`. Single-file only — cross-file reorder lives in the Chapters tab.
- `ProjectPanel.svelte` — replaces the old `GitPanel.svelte`. Contains the project header, "Save Version" card, change list with checkboxes, always-visible history, auto-backup status footer, collapsible "Advanced" section for cloud sync
- `CommentsPanel.svelte` — fifth sidebar tab. Lists comments for current file or whole project, body textarea with 400 ms debounced auto-save, resolve/delete actions, anchor-click jumps editor + flashes the highlight. Pushes decorations only on comment-list changes (NOT on `editorVersion` — that caused an infinite loop; the plugin handles `tr.docChanged` itself)
- `ProjectSearchPanel.svelte` — slide-in for `Cmd+Shift+F`. Live-debounced search with options Aa/W/.*/.bib, results grouped by file, click jumps + scrolls + briefly highlights. Reads `projectSearchPreset` on mount and clears it (consume-once)
- `VersionDetail.svelte` — modal for one history entry with source-text diff (red/green lines) and "Restore this version"
- `BackupListDialog.svelte` — auto-backup browser with collapsible settings (interval, max count, max AI snapshots)
- `ExportDialog.svelte` — format picker (PDF/DOCX) with chapter checkboxes; only opens for multi-chapter projects, single-file exports skip straight to the save dialog
- `CitationHoverCard.svelte` — popover shown after 350 ms hover on a `@citekey` badge. Reads bib metadata from `getCitationEntries()`, calls `project:findSourceForCitation` to detect a `sources/<citekey>*.pdf`, and exposes an "Open PDF" button that opens the source as a regular PdfFileViewer tab. Owns its own close-with-grace-period (250 ms) so the user can move from badge to card without the card vanishing.
- `ReferencePicker.svelte` — modal triggered by `/Reference`, `Edit → Insert Reference…`, or `Cmd+Alt+L`. Lists all `<label>`s grouped by type with caption preview and `relPath:line`. Keyboard nav (↑↓ Enter Esc), filter input, type-tabs. Picker calls back via `onPick`; App.svelte inserts a `reference` node at the cursor.
- `CrashReportDialog.svelte` — boot dialog mounted by App.svelte's onMount when `crash:getLatest` returns an unshown report. Two-view modal (intro → detail), buttons: Copy / Mail / Open folder / Discard / Close. Closing in any path runs `crash:markShown` so the same report doesn't reappear next boot.
- `StartScreen.svelte` — visible when no project is open. Three action cards (`New Project` / `Open Sample Project` / `Open Project`) plus a recent-projects list. The Sample button invokes `project:openSample` which copies `resources/sample-project/` to the user's chosen location.

`messageHandler.ts` listens for backend events including `projectClosed` (resets all editor state), `showExportDialog` (opens ExportDialog), `backupCreated` (refreshes the auto-backup status line), `aiSnapshotCount`. It also handles native-menu-driven renderer state changes: `showSearch`, `showProjectSearch`, `showShortcuts`, `addComment` (re-dispatches as `penwright:add-comment` window event), and forwards main-process menu actions (`requestSettings`, `mergeDocument`, …) to the main `penwright` switch via `MENU_MAIN_ACTIONS`.

### Editor (`src/editor/`)

TipTap-based rich text editor with ~19 custom Typst node extensions (`typst*.ts`). Key modules:
- `serializer.ts` — TipTap JSON → Typst source
- `deserializer.ts` — Typst source → TipTap JSON. Handles `#align(spec)[…]` blocks (incl. combined alignments like `center + horizon`), unwraps nested `#text(size, weight)[…]`, recognises `#datetime.today().display(…)`. Multi-line list items (`+ item\n  cont.`) are joined. Inline `#footnote[…]`, `#emph[…]` (→ italic), `#strong[…]` (→ bold) and `#raw("…")` (→ code) are parsed into nodes/marks. **`isRawBlock` strips known inline constructs across the whole block, not per-line** — otherwise a multi-line `#footnote[…]` body looked bracket-unbalanced and the whole paragraph was misclassified as raw code (Session 25). New inline mappings reuse existing mark/node types, so the TipTap→Typst serializer round-trips them as `_x_` / `*x*` / `` `x` `` / `#footnote[…]` (a benign normalisation, compiles identically).
- `reconciler.ts` — Incremental document updates
- `typstFootnote.ts` — Inline atomic node `footnote` with click-to-edit popup. Exports `insertFootnoteWithEditor(editor)` — inserts an empty footnote and synthesises a click on the freshly mounted DOM node so the popup auto-opens. Used by both the toolbar Fn button and the `/Footnote` slash command.
- `typstCitation.ts` — Inline atomic node `citation` (`@citekey` badge). `contextmenu` handler dispatches `penwright:find-backlinks` with `@<citekey>` (whole-word) so right-click finds every usage in the project. `mouseenter` starts a 350 ms dwell timer that dispatches `penwright:citation-hover` with `{ citekey, rect }`; `mouseleave` dispatches `penwright:citation-leave`. The hover card (App.svelte) decides whether to mount.
- `typstReference.ts` — Inline atomic node `reference` (`@label` cross-ref badge). Visually distinct (orange ↳ pill) from citation badges. Serializes to `@label` exactly like a citation; the deserializer's `isReferenceLabel()` heuristic decides which kind a parsed `@name` is — labels with a colon OR matching a known prefix (`fig|tbl|eq|sec|chap|app|thm|lem|def|cor|prop|algo|lst` and full forms) become reference nodes; bare slugs stay citations. `@` is **not** a UI trigger for references — the picker is the only insertion path.
- `commentDecorations.ts` — TipTap extension that renders gold-yellow inline decorations for active comment anchors **without modifying the document**. `setCommentMarks(editor, marks)` pushes a new mark list via plugin-meta transaction. The plugin's `apply()` rebuilds decorations on `tr.docChanged` itself — DO NOT trigger `setCommentMarks` from a `$effect` that tracks `editorVersion`, that loops infinitely (transaction → onTransaction → editorVersion++ → effect → transaction).
- Svelte components: `Toolbar.svelte` (Fn / Cm buttons + the `＋` Insert dropdown), `SettingsPanel.svelte`, `SearchReplace.svelte`, `ShortcutCheatsheet.svelte`, `WelcomeScreen.svelte`. (Retired components: `CommandHub.svelte` (Session 11); `QuickSettings.svelte` gear popover (i18n session); the **integrated terminal**, **Focus / Typewriter / Reading modes**, and the unused **`src/cli/`** were all removed in the focus-cut session — font-size / line-spacing live in the Design panel, document language in Document Settings.)

### Shared Code (`src/shared/`)

Code used by both main and renderer: settings parser, bib parser, DOCX serializer, style/project templates, document merge/split, markdown importer. Also `skillTemplates.ts` — five Claude-Code-skill string constants (`TYPST_SKILL`, `PENWRIGHT_SKILL`, `RESEARCH_SKILL`, `WRITING_STYLE_SKILL`, `DESIGN_SKILL`) with tilde-fenced code blocks (avoids backtick escapes in TS template literals); `projectManager.ensureClaudeSkills` deploys these to `<project>/.claude/skills/<name>/SKILL.md` per-file. The MCP server (`mcp/server.ts`) exposes the same skills as prompts (`typst-reference`, `penwright-conventions`, `research-workflow`, `writing-style`, `design-conventions`) by reading them out of the project's `.claude/skills/<name>/SKILL.md`. ### Internationalization (i18n)

The UI is fully bilingual (**English + German**, switchable at runtime). Infrastructure lives in `src/shared/i18n/`:
- **`en/<ns>.ts` + `de/<ns>.ts`** — one file per namespace (23 namespaces: `common`, `settings`, `menu`, `mainDialogs`, `design`, `look`, `designAi`, `onboarding`, `mcp`, `backup`, `crash`, `version`, `project`, `comments`, `exportDialog`, `sidebar`, `pickers`, `app`, `startScreen`, `license`, `about`, `editor`, `editorLib`). **`en` is the source of truth for the message SHAPE**; each `de/<ns>.ts` is typed `: <Pascal>Messages` (imported from `en/<ns>.ts`) so a missing/mis-shaped key is a compile error. Interpolated strings are function entries (e.g. `exportedTo: (fmt, file) => …`). **Pitfall:** a bare ternary of string literals (`(n) => n === 1 ? 'word' : 'words'`) infers a literal-union return type — annotate `: string` so the German translation stays assignable.
- **`index.ts`** (main-safe, no Svelte) — merges `en`/`de` into `dictionaries`, exports `Locale = 'en'|'de'`, `Messages = typeof en`, `normalizeLocale()` (maps `'de-DE'`→`'de'`, else `'en'`), `resolveDict(locale)`.
- **`store.svelte.ts`** — the reactive layer (Svelte 5 runes), imported ONLY by `.svelte` files. `i18nState.locale` is the `$state`; **`t()` returns the active dictionary** — call `t().<ns>.<key>` inside a template/`$derived` and it re-renders on switch. `setLocale()` applies + persists via IPC; `applyLocale()` applies without persisting (boot path). Seeds from `navigator.language` to avoid a first-paint flash.

**Import rules (critical — `tsconfig.json` has no `paths`, so tsc can't resolve `@shared` in tsc-checked files):**
- `.svelte` files (not tsc-checked) → `import { t } from '@shared/i18n/store.svelte';`
- Plain `.ts` files (tsc-checked: editor node-views in `src/editor/lib/*`) → **relative** `import { t } from '../../shared/i18n/store.svelte';` — NEVER `@shared`.
- **Main process** must NOT import the rune store → `import { resolveDict } from '../shared/i18n'` + `getLocale()` from `persistenceManager`, resolved **at the call site** (`resolveDict(getLocale()).mainDialogs.x`) so it follows the live language. Used by `menuBuilder.ts` (native menu) and all `dialog.*` calls in `fileManager`/`projectManager`/`importExport`/`ipcHandlers`.

**Persistence + selection:** global (per-device) `locale` lives in electron-store (`persistenceManager.getLocale`/`setLocale`; `null` default → resolved from `app.getLocale()` on first launch). IPC `app:getLocale`/`app:setLocale` (whitelisted in `preload-entry.ts`); `app:setLocale` also calls `buildMenu(appState)` to relabel the native menu live. App.svelte loads the locale on mount. The **language dropdown is the "Interface" section of the Document Settings dialog** (`SettingsPanel.svelte`), bound straight to `setLocale` (independent of the per-document `onSave`). That dialog needs a project open — first-run language is OS-detected, so the StartScreen still shows in the right language without its own switcher.

**Conventions:** top-level computed text (label maps, option arrays) → wrap in `$derived(...)`; transient/handler strings → call `t()…` at call time. Reuse `t().common.*` only when the meaning matches exactly. Editor node-view popups (`editorLib`) read `t()` when their DOM is (re)built — already-open popups don't live-update (fine, they rebuild on reopen). To add a namespace: create `en/<ns>.ts` (+ `<Pascal>Messages` type) and `de/<ns>.ts`, then register it in **both** `en/index.ts` and `de/index.ts`.

Configured in electron.vite.config.mts: `@shared` → `src/shared/`, `@editor` → `src/editor/`.

## Key Patterns

- **Preload whitelist:** any new IPC channel must be added to the allowed lists in `preload-entry.ts`. `SEND_CHANNELS`/`ON_CHANNELS` hold just the `Penwright` event channel; most new work goes into `INVOKE_CHANNELS`.
- **Typst compilation** always targets the root file (for multi-chapter support) and outputs PDF only. Never call `'typst'` directly — always use `getTypstPath()` so bundled-vs-system resolution works. For the args list, use `buildTypstCompileArgs(['<input>', '<output>'])` from `typstPath.ts`; it prepends `--package-path` so the bundled Typst packages (cetz, fletcher, showybox, codly, ...) resolve offline. The MCP server has its own `typstCompileArgs()` helper that reads `TYPST_PACKAGE_PATH` from env (set by the MCP setup wizard).
- **Preview-update mode (auto / manual)** — a **global** electron-store setting (`previewMode`, `persistenceManager.getPreviewMode`/`setPreviewMode`; IPC `persist:getPreviewMode`/`setPreviewMode`). It gates **only** the save-triggered recompile in `fileManager.saveFile()` (`if (getPreviewMode() === 'auto') compiler.compilePdf()`). The initial compile on open, external/AI watcher changes, and Undo-AI-Edit still recompile regardless (they're not "while typing"). In manual mode the file is still saved; the preview waits for the **Refresh button** (`preview:compile` IPC → `getCompiler().compilePdf()`). Chosen in the **Settings dialog → Preview** section. The renderer mirrors it in `previewState.mode` + tracks `previewState.dirty` (set on editor `onUpdate`, cleared on `previewPdfUpdate`/`compileError`) for the "Outdated" hint + Refresh-button accent.
- **Preview follows the active chapter** — on file switch the renderer sets `previewState.scrollTarget` to the open chapter's title (`firstHeadingTitle()` in `messageHandler`, computed in the `'update'` handler — fires on open/switch/external edit, never on keystrokes). It reads a native `= heading` first, then falls back to a `title: "…"` / `title: [...]` macro argument so magazine/design templates work too (e.g. `#opener(title: "Editorial")`, which still emits a real `heading` → PDF bookmark). `PdfPreviewPanel` reacts (effect guarded by `lastScrolledTarget` so it scrolls only when the target *changes*, never on plain recompiles), reads the PDF bookmarks via pdf.js `getOutline()`, fuzzy-matches the title, resolves the destination → page, and scrolls. Degrades to no-op if the PDF has no outline or no match. Still compiles the **whole** root doc (never a single chapter — that would drop global page numbers / styles / cross-refs).
- **Bundled Typst packages:** 24 packages live under `resources/typst-packages/preview/<name>/<version>/` (13 user-facing + 11 transitive deps). `scripts/fetch-typst-packages.mjs` pulls them from `packages.typst.org`. `scripts/audit-bundled-deps.mjs` runs as part of `package:*` and fails the build if any LICENSE classifies as GPL/AGPL or doesn't match its `typst.toml` declaration. The audit emits `THIRD_PARTY_LICENSES.md` at the repo root and `resources/typst-packages/bundle-licenses.json` for the in-app Acknowledgments dialog. Bundled list lives in the script's `PACKAGES` array — that's the single source of truth.
- **pdfjs `ArrayBuffer` is single-use:** `pdfjsLib.getDocument({ data })` transfers the buffer to the worker (zero-copy optimization), leaving it detached in the main thread. Re-calling `getDocument` with the same `data` throws `DataCloneError: ArrayBuffer is already detached`. When the document needs to update (zoom, scale changes), keep the loaded `currentPdf` and re-call `page.getViewport({ scale })` + `renderPage` instead of recreating the document.
- **Document zoom** is two independent levels: editor uses CSS `zoom: var(--editor-zoom)` on `.editor` (Chromium reflows the layout correctly, ProseMirror selection coordinates stay accurate — unlike `transform: scale` which breaks them); PDF uses pdfjs viewport scale `BASE_SCALE * pdfZoom` plus a proportional placeholder width so horizontal scroll kicks in above 100 %. Both are stored per-project in `.penwright/preferences.json` and shared between the live preview (`PdfPreviewPanel`) and source-PDF tabs (`PdfFileViewer`).
- **External file changes** are detected via chokidar; the watcher uses a 3-second timestamp guard (`lastSaveTimestamp`) to ignore self-triggered events. The watcher also ignores `**/.penwright/**` so backups never trigger refresh loops.
- **Five independent project-local persistence layers** — keep them conceptually separate:
  - **Versions** (Git): user-triggered "Save Version" → `git commit`. Lives in `<project>/.git/`. Use the high-level handlers (`git:saveVersion`, `git:listVersions`, `git:restoreVersion`); the low-level verbs are kept for the "Advanced" cloud-sync UI only.
  - **Auto-backups**: timer-driven multi-file snapshots in `<project>/.penwright/backups/<timestamp>/`. Each snapshot is a flat folder of files plus a `.meta.json`. On open, `checkForFileRecovery()` offers to restore if the latest backup is newer than the disk file.
  - **AI-edit snapshots**: ring buffer in `<project>/.penwright/ai-snapshots/`, persisted as JSON per entry, restored into memory on project open. Used by "Undo AI Edit" — never confuse with versions.
  - **Preferences**: `<project>/.penwright/preferences.json` holds per-project UI knobs (currently `editorZoom`, `pdfZoom`). Read/written via `getProjectPreferences` / `saveProjectPreferences`. Loaded on first `currentFile` event after open (cached by projectDir to avoid re-loads on file switches inside the same project); reset to defaults on `projectClosed`. Debounced save on change. When adding new per-project UI settings, extend this file rather than electron-store.
  - **Style** (Design-Editor — Sessions 21–23.2): `<project>/.penwright/style.json` holds the typed "design tokens" via `getProjectStyle` / `saveProjectStyle` / `hasProjectStyle` (`persistenceManager.ts`). Schema covers colors (5 semantic slots), fonts (body / heading / code), scale (base / leading / paragraphSpacing / firstLineIndent), layout (paper / orientation / margin / columns / pageNumbering / pageHeader / pageFooter / pageFill), headings h1–h6 (size / weight / color-slot / marginTop) + numbering, elements (blockquote / codeBlock / figure with `creditSeparator` + `creditLabel` for photographer credits / table), and `custom.preamble` (free-form Typst escape hatch). Schema + sanitizer in `src/shared/styleTypes.ts`. `style:save` regenerates `<project>/style.typ` via `generateStyleTypst()` (`src/shared/styleParser.ts`) and ensures the root file has `#import "style.typ": *` + `#show: apply-style` at the top (legacy `#include "style.typ"` is auto-migrated by `ensureStyleInclude`). **The design home is resolved by `resolveStyleRootFile()`** (ipcHandlers) — prefers a project-root candidate (`main.typ` / `document.typ` / `index.typ`) over `findRootFile(openFile)`, so **global style is never written into an open chapter** (which would inject page setup + a duplicate `apply-style` show rule and break compilation). `style:get` also returns the root basename so the Design panel can label its scope. The MCP `writeProjectStyleAndRegenerate` uses the same candidate order. The fenced custom-code block is round-tripped via `extractCustomBlock()` — manual edits to that section survive regeneration. The generated `style.typ` exports four module-level values besides the `apply-style` function: `style-colors` (palette dict), `style-fonts` (body/heading/code dict), `figure-caption-credit(caption, credit)` (helper for photographer captions, uses the configured `creditSeparator` + `creditLabel`), and the running-head helpers `chapter-name()` / `section-name()` — header/footer markup strings can use `{chapter}` / `{section}` placeholders that the generator substitutes with these calls (`substituteRunningHeadPlaceholders` in `styleParser.ts`). **Presets** live in three places: `palettePresets.ts` (8 color-only), `themePresets.ts` (6 full ProjectStyle snapshots — Classic Academic, Modern Tech, Editorial Magazine, Minimal, Marketing Brochure, Thesis), `layoutPresets.ts` (7 layout-only swaps — A4 portrait/landscape, 2-col magazine, 3-col newsletter, A5 booklet, A2 poster, Magazine Editorial with per-chapter running head). Theme apply preserves `custom.preamble`; layout apply only swaps `layout.*` and optionally `scale.base`. - **Safe-apply engine ("every design change is a safe experiment"):** all in-app design mutations (`style:save`, `section:apply`, `section:clear`) route through **`safeApplyDesign(writes, label)`** in `ipcHandlers.ts` — it stages the file writes, runs **`TypstCompiler.verify()`** (a one-off compile to a separate temp PDF, no preview events), and **commits** (emits the fresh preview + records an undo entry) only if it compiles; otherwise it **rolls back** the files and leaves the last-good look on screen. `appState.lastCompileOk` (set by the preview compiler's `compiledPdf`/`error` listeners) gates the verify so a design action is never blamed for a *pre-existing* content error (if the doc was already broken, the change commits without a verify). Handlers return `{ ok: false, kept: true }` on rollback; the renderer reverts its controls (`reloadStyleFromDisk`) + shows a "nicht angewendet" note. A bounded in-memory **design-undo stack** (`design:undo` / `design:canUndo`) powers the DesignPanel "↩ Rückgängig" button. **Any new in-app design mutation MUST go through `safeApplyDesign`** — never write design files then compile after; that's how the doc used to end up non-compiling with no easy undo. (AI/MCP edits keep their own AI-snapshot undo; the watcher path is separate.)
