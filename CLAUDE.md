# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

vswrite-desktop is a standalone Electron desktop app for WYSIWYG editing of Typst documents, ported from the vswrite VS Code extension. Tech stack: Electron 41, electron-vite 5, Svelte 5 (runes), TipTap/ProseMirror 3, simple-git, pdf.js. Typst CLI is bundled with the app (no user installation needed).

The app is **project-first**: every file lives inside a project folder. Each project is self-contained — the Git history (`.git/`), auto-backups (`.penwright/backups/`), AI-edit snapshots (`.penwright/ai-snapshots/`), and per-project UI preferences (`.penwright/preferences.json`) all live inside the project, so copying or moving the folder takes the full state with it. The app starts at the Start Screen and never auto-reopens a project.

## Naming Convention (Penwright — read before introducing new identifiers)

The product was renamed **vswrite → Penwright**. **Canonical name is `Penwright` (prose / UI) and `penwright` (identifiers).** All new code, tools, UI text, IPC channels, events, CSS classes, log tags, protocols, and the project state folder (`.penwright/`) MUST use `penwright`/`Penwright`. There should be **no new `vswrite`** anywhere. License keys are `pw_LIC…`; the support email is `feedback@penwright.online`.

**Intentional `vswrite` holdouts** (do NOT "fix" these — they are deliberate):
- **`vswrite-desktop`** — the git repo + working-directory name. Renaming it would break clones, remotes, and absolute paths. Stays until/unless the repo itself is renamed.
- **`.vswrite` literals in `projectManager.migrateLegacyProjectDir`** — the one-shot `.vswrite/` → `.penwright/` migration must reference the *old* folder name to find and rename it. Intentional.
- **Historical docs** — `documentation/done/**`, `documentation/handover.md`, and the changelog `documentation/project_status.md` are kept as accurate history (e.g. "ported from the vswrite VS Code extension", session entries describing the rename). Not rewritten.

The electron-store filename was renamed `vswrite-settings` → **`penwright-settings`** — no migration, so the prior global state (recent projects, license blob, trial-start date) resets once on first launch.

**Web domain:** canonical is **`penwright.online`** (Website button, manifest homepage/support, support email `feedback@penwright.online`). The **User Guide ships in-app** — `HandbookViewer.svelte` renders the bundled handbook (`documentation/handbuch.md` for German UI, `handbook.md` otherwise); there is no external docs site. `penwright.online` still needs to be registered before the website/pricing links resolve.

**Point the corpus at real work — this is where the bugs are.** `penwright.corpus.json` (git-ignored, see `penwright.corpus.example.json` / `scripts/corpusConfig.mts`) names project folders outside the repo; both corpus suites read it. Every content-destroying round-trip bug found so far was found this way, not in the presets. `compile-corpus-test` resolves a root **by elimination** (the top-level `.typ` no sibling `#import`s) and walks a folder *of* projects, because real roots are called `Angebot.typ`, not `main.typ`. Consequence worth knowing: editing those documents can turn `npm test` red in this repo — that is the gate working, not a bug.

**Two measurement traps in the pixel gate, both of which produced confident false alarms.**
- **Hash the pixels, not the file.** Typst 0.15 ships "space-optimized output by default", so the same page re-encoded from 397 KB to 181 KB with byte-identical pixels. A file hash called all 39 corpus projects changed on every page — 100 % false positives. `typstRender.pngPixelHash` inflates the IDAT and undoes PNG scanline filtering (Node `zlib` only, no dependency, cross-platform); cross-checked against macOS `sips`.
- **Ignore system fonts, or you measure your own font folder.** The same comparison reported six pages of "reflow" that were entirely local: `~/Library/Fonts` holds a Crimson Pro **variable** font, 0.15 can instance it at `weight: "medium"` and 0.14.2 could not. Isolated, those pages are identical between the two compilers. The app deliberately does NOT ignore system fonts (a user who installs a font should be able to use it) — a test must. Every shipped preset was verified font-self-contained, so isolating costs no coverage.

**Two test traps that have each cost a day. Neither is hypothetical.**
- **Green by absence.** `compile-stability-test` exited 0 when its project folder was missing, so the strongest test in the repo reported "passed" on every machine but one, having compared nothing. A skip that reads as a pass buys confidence it did not earn — both compile suites now exit 1 and need an explicit `--allow-skip`. **Run every new test once against the removed fix.** If it does not go red, it is testing something else. (`roundtrip-corpus-test` was green over all 153 files against a deserializer that flattened every attached bullet list into prose — its `normalise()` collapsed newlines, so "list" and "prose with dashes" were the same string.)
- **Flaky is off.** `watch-ignore-test` waited a flat 1200 ms for chokidar; under load macOS drops the deepest path's notification and the gate failed for no reason. A gate that fails at random gets re-run until it is green. Wait for the event you expect and retry the trigger — one lost FSEvent is not evidence.
- **Quelltext-Assertions.** `style-guard` once regex-matched the *source text* of a function; the function moved to `shared/` and the regex would have gone green by finding nothing. Assert behaviour.

Plus one non-test guard, wired into `package:*` so a release cannot ship past it:

```bash
npm run check:mcp     # scripts/check-mcp-tool-consistency.mjs
```

`src/mcp/server.ts` is the truth for the tool list; the script fails the build when a doc, the handbook, the skill or the `.mcpb` manifest names a tool that does not exist, states a count that is wrong, or misses one that does. It also enforces the wrapper invariants above (no direct `server.tool`, no `outputSchema`, every tool in `TOOL_META`, `instructions` passed and under 2 KB). **The `.mcpb` manifest's tool list is now generated from the server** by `build-mcpb.mjs` rather than hand-maintained — it had drifted to ten tools missing.

**Two things this script is deliberately lenient about:** `documentation/done/**` and the planning documents are history, and a plan describing a tool it proposed to build is a record, not drift. Flagging those would teach everyone to ignore the script, which is the only way it can actually fail.

`npm run build:mcp` first for anything that spawns the server — the E2E suites run against `dist/mcp/server.mjs`, not the sources, so a stale bundle silently tests the previous version.

## Architecture

### Process Model

Three build targets configured in `electron.vite.config.mts`:
- **Main process** (`src/main/index.ts`) — Window management, file I/O, IPC routing, git
- **Preload** (`src/main/preload-entry.ts`) — contextBridge with whitelisted channels (contextIsolation: true, nodeIntegration: false)
- **Renderer** (`src/renderer/main.ts` → `App.svelte`) — Svelte 5 UI shell, panels, state

Build outputs go to `dist/main/`, `dist/preload/`, `dist/renderer/`.

### Main Process Modules

`appState.ts` is a leaf-module singleton imported by all other main modules — never import project modules into it (circular dependency prevention). The remaining modules are organized by domain:

> **Pitfall — never use a runtime relative `require('./x')` in the main process.** electron-vite bundles the whole main process into a single `dist/main/index.js`, so a relative `require('./typstPath')` / `require('./appState')` at runtime throws "Cannot find module" (there are no sibling `.js` files). Always use a static `import` — the bundler inlines it. This silently broke `app:checkTypst` (always returned `false` → permanent "Typst not found" even with Typst bundled) and dropped the project-context block from every crash report; both fixed by converting to static imports.

- `ipcHandlers.ts` — Central IPC message router dispatching to:
  - `fileManager.ts` — File I/O, auto-save (1s debounce), chokidar watcher (3s timestamp guard to prevent sidebar flicker), compiler invocation, AI snapshot ring buffer persisted to `<project>/.penwright/ai-snapshots/` (configurable max), project-local auto-backup timer (configurable interval), `closeProject()` / `closeProjectInteractive()` for clean teardown. Adds breadcrumbs to `crashReporter` on save / open / close.
  - `importExport.ts` — PDF + DOCX export with chapter-selection modal, Markdown import, Zotero, style templates. `runFilteredExport()` writes a temporary filtered root file (`.penwright-export-temp.typ`), compiles, and cleans up. DOCX uses `resolveIncludes()` from shared to merge the project before serialization, then passes the project style **and** a `renderTypstSnippet` callback (`createTypstSnippetRenderer`) into `serializeDocx`. As of Session 25 the DOCX serializer (`src/shared/docxSerializer.ts`) no longer dumps `typstRawBlock`s as monospace — it classifies + renders them (`#figure` → image/table + numbered caption (incl. `caption: "…"` strings and `figure-caption-credit("…", "…")` photographer credits), display-math + SVG → rasterised via the injected callback, `#quote` → Quote, gentle-clues callouts → accent box, prose-with-inline → a real paragraph; pure layout/design code is skipped). Session 33 extended it: text-carrying design containers (`#align` / `#block` / `#dropcap` / `#wrap-content`, also behind leading `#v()` spacers — title heroes, pull-quotes, drop-cap paragraphs, wrap-it prose) emit their visible text as styled paragraphs (`#text(size/weight/style)` → run size / bold / italic) instead of being dropped; heading labels (`= Title <sec:x>`) are stripped from the heading text and registered as `Section N.M` cross-ref targets; adjacent `@a @b` citations collapse into one `(A et al., 2021; B et al., 2021)` group; the bibliography renders APA-shaped ("References" heading, `et al.`, en-dashes, DOI/URL). The math/SVG renderer is injected (not imported) so `shared/` stays dependency-free; the MCP server wires its own (`createMcpSnippetRenderer`).
  - `projectManager.ts` — Project templates, `openProject()` (folder picker), `openSampleProject()` (resolves `resources/sample-project/` from `process.resourcesPath` in production, copies it to a user-chosen location, runs `git init` + initial version, then opens), `ensureProjectInfrastructure()` (lazy `git init` + `.gitignore` + `.penwright/` skeleton + initial commit), `handleNewFolder()` and `handleAddAssets()`. Skill-template content lives in `src/shared/skillTemplates.ts`; deploy is per-file (not dir-level) so user customisations to one skill don't block updates to another. Project templates are defined in `src/shared/projectTemplates.ts` (6 templates: document / thesis / paper / letter / book / **magazine**). The `magazine` template is designed for the [ai-magazine-designer](https://github.com/renejes/ai-magazine-designer) Slow-Media pipeline — ships `chapters/_cover-macro.typ` (stable `magazine-cover` macro definition) + `chapters/00-cover.typ` (macro call, rewritten by the cover-designer skill per issue) + editorial + TOC chapter slots. No `.penwright/style.json` shipped; the typst-architekt skill calls `penwright_generate_layout("magazine")` or `penwright_update_style` on demand if it wants Design-Editor integration.
  - `gitManager.ts` — Low-level Git verbs (status/stage/commit/push/pull) plus high-level "Versionen" API: `git:saveVersion`, `git:listVersions`, `git:showVersion` (parses unified diff), `git:restoreVersion`, `git:getRemote`/`setRemote`
  - `projectSearch.ts` — Project-wide find & replace across `.typ` (and optionally `.bib`), regex/case/whole-word, max 1000 hits with truncation flag. Whole-word uses `(?<!\w)…(?!\w)` lookarounds — **NOT** `\b…\b`, because `\b` doesn't fire when the term starts with a non-word char like `@` (citation backlinks would silently return zero hits otherwise). Live in-memory content for the open file is searched alongside disk content. Optional `projectDir` parameter (dual-tauglich) so the same code drives the IPC handler and the MCP `penwright_search_project` tool.
  - `projectLabels.ts` — Powers the cross-reference picker. Walks every `.typ` file (skipping `.git`, `.penwright`, `assets`, `sources`, `comments`), pulls `<label>` matches and best-effort captions (heading text, nearest `caption: [...]` in a `#figure(...)`, equation snippet, or text-before-label fallback). Classifies each label by name prefix (`fig|tbl|eq|sec|chap` etc.). Capped at 2000 labels with a truncation flag. Same dual-tauglich pattern as `projectSearch`.
  - `commentManager.ts` — Comments live as `<project>/comments/<id>.md` (sortable id like `2026-04-28-1432-a3f`), one Markdown file per comment with YAML frontmatter (`id`, `file`, `anchor`, `rangeStart/End`, `author`, `date`, `resolved`) + Markdown body. Visible folder, cloud-sync-friendly, never compiled into PDF/DOCX. Reanchoring: exact offset hit → `indexOf` from `rangeHint - 200` → global → `orphaned: true`. Has its own minimal YAML parser (no external dep).
  - `projectMacros.ts` — **The project's own building blocks** (Session 47, Stufe 1 of the handover plan). The 24 shipped design elements are a list *we* wrote; a real project — above all one an AI has designed — invents its own (`#modul`, `#insight`, `#sumrow`, `#box-choice`), and until now none of them could be inserted from the UI at all. The catalogue is **derived, never declared**: a module-level `#let name(params)` is a building block, and a `//` comment directly above it becomes its label. Requiring registration would leave the catalogue empty on every project that already exists. Names starting with `_` and `#show` entry points (`apply-style`, `*-style`) are excluded — inserting the latter mid-chapter is the corruption `resolveStyleRootFile` exists to prevent.
    - **Visibility is PER FILE and that is load-bearing.** Proven against the bundled compiler: `#import "macros.typ": *` in the ROOT does **not** reach an `#include`d chapter (`error: unknown variable`), so a project-wide catalogue would offer a chapter macros that cannot compile there. Star imports **do** re-export transitively, so `visibleIn()` walks the import graph rather than one hop; a named import narrows what a module contributes and keeps narrowing through *its* imports.
    - **`src/shared/macroCall.ts`** is the one call builder — main, renderer and MCP all call `buildMacroCall()`, per the shared-planner rule. Two behaviours in it were read off 36 real call sites, not guessed: the body goes to the parameter **named** `body`-ish (NOT "the last positional" — `#note(body, title: …)` is called `#note(title: …)[…]`), and a `path`-ish parameter names a **file**, so a word placeholder is a compile error rather than a placeholder (`#aufmacher(path, …)` hands it straight to `image()`).
    - **Editing an instance (Session 47, Stufe 2).** A raw block that is EXACTLY one call to a visible project macro renders as a **card** — label plus its values — with a click-to-edit form and a `</>` escape hatch back to the textarea. `findMacroForBlock()` is **the single, swappable recognition function** the handover's §3 "Bauprinzip" demands: every surface asking "does this get a form?" goes through it, so tomorrow's CST swap touches one function instead of the seven scattered scanners `deserializer.ts` grew.
      - **Nothing is ever regenerated.** `parseMacroCall` returns OFFSET RANGES (JS string indices, *not* UTF-8 bytes — the corpus is German and the two differ on almost every real call) and an edit splices exactly one span. The author's line breaks, trailing commas and comments survive, and so does every value nobody touched — `#datetime.today()` in a sibling argument must still be `#datetime.today()` afterwards, not the day it was edited.
      - **The parser refuses far more than it accepts, on purpose.** Anything that is not one whole call — prose around it, two calls, an unclosed delimiter, a method chain — returns null and keeps the textarea. A trailing `[…]` binds ONLY when byte-adjacent (compiler-verified, and stricter than it looks: a space, a newline, even `/* c */` between `)` and `[` all give `missing argument`), which is what stops the LANGSAM interview's `#frage[question]` from swallowing the answer block under it.
      - **Three Typst facts, each measured against 0.15.1 rather than reasoned about, each a corruption if guessed:** a `[…]` body is MARKUP, so `(` `)` `{` `}` are literal there and `"` is a quotation mark (getting this wrong made `#note[Ein Wert (mit Klammer]` "unparseable" and locked the form out of the block it had just written — the third time this repo has paid for uniform delimiter counting); `//` IS a comment in markup and eats the closing `]`; but `http://` and `https://` are exempt and **only** those — `ftp://`, `mailto://` and a bare `://` are comments again.
      - A field for a parameter the call omits shows empty and means "the `#let` default"; emptying it again REMOVES the argument rather than writing `""`. An `isPath` parameter gets a **file picker** (`project:pickAsset`, request/response, routed through the same `placeAssetFromPath` as every other image entry point) — a text box asking a non-Typst user to type a relative path is the one thing the form exists to avoid. **The path it writes is relative to the macro's DEFINING file, not to the open chapter** — the renderer passes `macro.filePath` and main re-checks it with `isPathWithin` before using it as a base, because that parameter is now an input channel. Getting this wrong was not a cosmetic slip: the picker wrote `../assets/…` into a call whose `image()` lives in `macros.typ` and the document stopped compiling. `ProjectMacro.resolvesPathsHere` records whether the macro's own body is where the path is consumed (derived by bounding the `#let` body with `matchTypstDelim` and looking for `image`/`read`/`bibliography`/`csv`/`json`/…); when it is false the macro only passes the value on, the base may be a third file, and the form says so instead of claiming a base it cannot prove.
      - **A comment is never part of a value.** `tightenRange` moves an argument's range past a leading or trailing `//` and `/* */`, and `splitTypstList` returns ranges already tightened, so a comment stays in the gap BETWEEN arguments where no splice reaches it. Before that, the field for `nr` in `#modul(\n  // Nummer\n  "2.1", …)` read `// Nummer "2.1"` and editing it wrote the comment away into `error: expected comma`. `projectMacros.ts` had its OWN paren reader and comma splitter, neither comment-aware, so `#let modul(nr, // die Nummer\n titel, body)` reported `nr, body` and every offered call was short an argument — **both scanners are gone**; `matchTypstDelim` and `splitTypstList` are the only ones.
      - A `path` parameter is **always** a string field, whatever its `#let` default looks like: a `bild: none` default made it an `expr`, so the file picker wrote the path unquoted and the document died with `unknown variable: assets`.
      - The walk is bounded by **`isPathWithin`** (realpath-based, so it catches a symlink) and so is the import graph — without it a `link.typ` pointing outside the project had its `#let`s, comment and all, listed in the user's insert menu and returned over MCP.
      - The form's logic (`macroFormFields` / `readMacroField` / `writeMacroField`) is **pure and in `shared/macroCall.ts`**, not in the node view, so `scripts/macro-edit-test.mts` drives the exact code the UI runs. The popup itself is `src/editor/lib/fieldPopup.ts`, extracted from `typstMagazine.ts` and generalised over how a value is read/written — the magazine nodes write `attrs`, a macro instance writes offset ranges into `content`, one popup. Writes read the node from the LIVE document (`tr.doc.nodeAt(pos)`, the `typstImage.applyAttrs` shape), because every keystroke is a dispatch and a closure copy lags one behind.
      - **Deliberate asymmetry:** there is no MCP tool for editing an instance. The form exists because the human cannot write Typst; the AI writes it natively and edits the source directly. `penwright_list_project_macros` gives it the same catalogue (P2/P3 hold).
    - Reached by `project:listMacros` (IPC, defaults to the open file), the `'project'` group in `getCommands()` — so the slash menu **and** the ＋ dropdown get it from the one source, under "From this project" / "Aus diesem Projekt" — and the MCP tool `penwright_list_project_macros`. `scripts/project-macros-test.mts` **compiles every generated call** against the fixture and against all five real corpus projects (63 macros); a signature read wrongly surfaces as `unknown variable`, not as a diff.
  - `citationSources.ts` — `findSourceForCitation(projectDir, citekey)` looks up `sources/<citekey>*.pdf` (exact match preferred, then suffix variants). Used by both the IPC handler `project:findSourceForCitation` and the MCP `penwright_find_source_for_citation` tool.
  - `crashReporter.ts` — Local crash reporter. `setupCrashCapture()` registers `uncaughtException` + `unhandledRejection` handlers, starts Electron's native Crashpad, enables `process.setSourceMapsEnabled(true)`. `addBreadcrumb(kind, msg)` feeds a 50-entry ring buffer; `captureMainCrash` / `captureRendererCrash` write plaintext to `<userData>/crash-reports/<timestamp>-<ms>-<rand>.txt` with username scrubbing for `/Users/<x>/`, `/home/<x>/`, `C:\Users\<x>\`. Boot detection compares latest mtime against `.last-shown` marker (uses `Number()` not `parseInt` so the float fraction doesn't get truncated). Rotation at 10 files. Renderer crashes arrive via `crash:report` IPC; the boot dialog is `CrashReportDialog.svelte`, mailto pre-fills `feedback@penwright.online`.
- `typstCompiler.ts` — Typst → PDF compilation only (SVG mode removed in Session 9 — was blocking the main thread on large docs). Emits `compiledPdf` event with raw buffer.
- `typstPath.ts` — Resolves the typst binary. Production: bundled at `resources/bin/typst-{arch}-{platform}`. Otherwise probes common locations (`/opt/homebrew/bin`, `/usr/local/bin`, `~/.cargo/bin`, …) and falls back to `command -v typst` via `/bin/sh -lc` because macOS GUI apps don't inherit Homebrew PATH.

Most items send a `Penwright` IPC message that ipcHandlers / messageHandler dispatches.
- `lockManager.ts` — File locking for shared folders (Dropbox, iCloud)
- `persistenceManager.ts` — Two-storage model. ### Editor (`src/editor/`)

TipTap-based rich text editor with ~19 custom Typst node extensions (`typst*.ts`). Key modules:
- `serializer.ts` — TipTap JSON → Typst source
- `deserializer.ts` — Typst source → TipTap JSON. Handles `#align(spec)[…]` blocks (incl. combined alignments like `center + horizon`), recognises term lists (`/ term: def`, kept verbatim). Multi-line list items (`+ item\n  cont.`) are joined. Inline `#footnote[…]`, `#emph[…]` (→ italic), `#strong[…]` (→ bold) and `#raw("…")` (→ code) are parsed into nodes/marks. **`isRawBlock` strips known inline constructs across the whole block, not per-line** — otherwise a multi-line `#footnote[…]` body looked bracket-unbalanced and the whole paragraph was misclassified as raw code (Session 25). New inline mappings reuse existing mark/node types, so the TipTap→Typst serializer round-trips them as `_x_` / `*x*` / `` `x` `` / `#footnote[…]` (a benign normalisation, compiles identically).

  > **The round-trip rule, learned from ten losses in shipped and client documents (Session 44): a WYSIWYG unwrap may only claim what the node graph can GIVE BACK.** Anything else keeps the whole block verbatim as a `typstRawBlock` — the call `typstGrid` and `typstHero` already make. Verbatim still exports; the DOCX and HTML serializers read design text out of raw blocks. Concretely: `#align(…)[…]` unwraps prose, an image, a heading and `weight: "bold"` and bails on everything else, because promoting `#text(size: 54pt, fill: …, font: …)` to `= Title` threw the size, colour and font away on three shipped title pages; a live `#datetime.today()` must never be rendered into a literal (it froze to the day of the first save); a term list has no node, so it stays verbatim rather than being escaped to a stray `\/`.
  >
  > **Tables carry their own styling verbatim (Session 47, Stufe 3).** `parseTable` used to demand `columns:` be a plain integer and bail on every other parameter, so **not one of the 27 real tables in the corpus was editable** — the price tables in the client offers included (21 write `columns:` as a tuple, 17 pass `align:`, 16 `fill:`, 9 `stroke:`, 8 use the `table.header[A][B]` bracket form). Now the whole leading parameter list is carried as SOURCE TEXT on the node's `params` attribute (declared by `TableParams` in `typstTable.ts` — an undeclared attr is silently dropped) and re-emitted untouched, so a hand-tuned `stroke:` survives byte-for-byte while the CELLS become editable. `columns:` is rewritten when the row shape actually changed — a stale `columns:` does **not** fail loudly, Typst silently reflows the table — and so are `align:` / `fill:` / `stroke:` / `inset:`, which are applied **per column** and **cycle** when short (measured: `align: (left, right)` on three columns renders exactly like `(left, right, left)`), so rewriting only the count would leave a new column silently inheriting column 1's styling. An array is only resized when its length matches the count the source declared — a shorter one means the author was relying on the cycling — and a **dictionary is never resized at all**: `inset:` and `stroke:` accept both forms, and `(x: 8pt, y: 4pt)` splits into two entries that look exactly like a two-column array. Resizing one duplicates a key and Typst refuses the whole document (`duplicate key: x`, verified), so `isTypstDictLiteral` gates every one of these. Growing repeats the last entry; the existing columns keep theirs (padding an array past the column count is pixel-invisible). **Two paths, because a count cannot say WHERE.** `src/shared/tableParams.ts` holds both: `shiftTableColumn(params, op, index)` runs in the EDITOR when the user adds or removes a column through the gear menu — the only place that knows the position, so a column inserted in the middle moves the entries after it onto the right columns and the new one copies the neighbour it was added beside. `reconcileTableParams(params, numCols)` is the count-based net for shape changes that never touch the table UI (an AI edit, a paste, an undo); it can only append or truncate, and says so. The editor applies the structural command and the parameter shift in ONE transaction, so the document is never briefly inconsistent and one undo takes back the whole edit. The gear menu offers column and row insertion on BOTH sides; the indices are prosemirror-tables' own (`addColumnBefore` → `rect.left`, `addColumnAfter` → `rect.right`, read from its source), and because `deleteColumn` removes the whole selected SPAN the removal loops `rect.right − rect.left` times at the same index.
  >
  > Three forms are remembered rather than normalised, purely to keep client files byte-stable: the header's bracket-vs-paren spelling (`headerForm`), and per cell whether it was written as a `"string"` or a `[content block]` (`literal`). Those are not cosmetic — `"*fett*"` renders the asterisks literally while `[*fett*]` renders bold, so a string must come back as a string, and only falls back to a content block once the user gives the cell real markup.
  >
  > **The cell checks its own round trip** (`cellRoundTrips`), and that guard is the load-bearing part. `parseInline` models a subset of Typst and silently drops the rest; claiming a table sent every cell through it, and two client offers lost a `\` linebreak and the `size:` out of `#text(size: 8.5pt, fill: mute)[…]`. **The pixel gate caught it as a whole extra page** — the text comparison did not. So each cell is parsed, written back and compared; anything that does not reproduce keeps the WHOLE table verbatim. 10 of 16 corpus tables are now editable, and the 6 refusals are refusals on purpose.

  > **Where Typst distinguishes two forms, the AST must carry which one.** A list directly under its intro line renders tighter than one after a blank line, so list nodes carry `attached` (set by the block splitter, declared in the schema by `typstListAttach.ts` — an attr ProseMirror does not know is silently dropped, which is what once lost heading labels) and `serializer.joinBlocks` re-emits one newline instead of two.
  >
  > **`splitIntoBlocks` tracks Typst's TWO MODES on a stack**, one frame per open construct (`[` opens markup, `(`/`{` open code, `#` opens a hash expression or statement), and counts delimiters per the mode it is actually in — strings and comments skipped throughout. Verified against the bundled compiler, because the asymmetry is the whole point: **in markup only `[` `]` group** (`(` `)` `{` `}` are literal, `"` is a quotation mark, `\[` escapes); **in code all six group** and `"` opens a string. Nothing groups in the file's own top-level markup — the body is not a bracket-delimited content block, and Typst accepts a lone `[` there.
  >
  > This replaced a single boolean seeded from three depth counters (`code = braceDepth > 0 || bracketDepth > 0 || parenDepth > 0`), which had the fault in it twice over. Once at the top level: an unclosed `(` in prose — a smiley — merged the rest of the file into one paragraph and **destroyed** every heading in it (mid-paragraph `=` is literal text to Typst). And once a level deeper, latent until Session 47: `bracketDepth > 0` means *we are inside a `[…]` body*, i.e. markup, and the line went into code mode anyway — so a `(` typed into a **macro body** did the same thing. Measured over the corpus, typing `Kosten (ca. 30% mehr. ` into the first macro body of each file cost **154 of 189 headings in the real client documents (29 of 49 files)** and 56 of 97 in the shipped presets. There the merged block starts with `#`, so it is kept verbatim as a raw block and no bytes change — the loss is structure, not content — but `Ein #emph[Wort]. Und dann (offen` merges into a **paragraph** and is destructive in the original sense.
  >
  > **Three regressions the stack itself introduced**, found by an adversarial review of the session that added it — all three byte-clean on a round trip, so no corpus or pixel gate could see them: a **line comment must `break`, not `return`**, or the `'!'` frame of a `#set … // Kommentar` outlives its own line and the next one is read as code (harmless before the stack, when `statement` was a local that died with the line); **`escaped` must count the RUN of backslashes**, because `\\[` is an escaped backslash followed by a REAL bracket, and calling it escaped leaves the body unclosed; and **`isRawBlock` must use Typst's own identifier rule** (`#[\p{L}_{(]`), not `#[a-zA-Z{(]` — the ASCII-only test escaped `#übersicht(…)` into literal text that printed as source in the PDF, which stayed latent until the macro catalogue started discovering `\p{L}` names and offering them.
  >
  > Two rules the stack must keep, each paid for by a bug: a **hash EXPRESSION reaches only as far as its own path** — `#sym.dagger` ends at the `r`, and opening a frame for it never closes one, which ate the `]` of the table cell it sat in (sample project + a client document, caught by re-parsing the unmodified corpus and finding *fewer* headings than before). And after a call's delimiters close, the chain continues only before `[`, `(`, or a `.` **followed by a field name** — a sentence-ending period is not a chain. `$` is still tracked in both modes (display math is markup and opens without `#`).
- `reconciler.ts` — Incremental document updates
- `typstMagazine.ts` — **Magazine AST nodes (Phase C keystone, Session 37).** Turns the load-bearing hand-written magazine macros from opaque `typstRawBlock` atoms into 9 real nodes so they carry to **PDF + DOCX + HTML in one step** and are WYSIWYG: `articleHeader` (← `opener`, **block atom**, 4 string fields, its title is the outline H1), `interlude` (← `interlude()`, atom), `marginNote` (← `randnotiz`, **inline atom** — sits mid-sentence like footnote, click-popup), plus **6 content nodes** (the codebase's first content-bearing custom nodes — `atom:false` + a `content` expression, body edits inline): `dropCap`/`question`/`pullQuote` (`inline*`) and `callout`/`figurePanel`/`columns` (`block+`). `aufmacher`/`doppelseite`/cover stay raw → Phase E. ### Internationalization (i18n)

The UI is fully bilingual (**English + German**, switchable at runtime). Infrastructure lives in `src/shared/i18n/`:
- **`en/<ns>.ts` + `de/<ns>.ts`** — one file per namespace (25 namespaces: `common`, `settings`, `menu`, `mainDialogs`, `design`, `look`, `designAi`, `onboarding`, `mcp`, `mcpConnection`, `backup`, `crash`, `version`, `project`, `comments`, `exportDialog`, `sidebar`, `pickers`, `app`, `startScreen`, `license`, `about`, `editor`, `editorLib`, `history`). **`en` is the source of truth for the message SHAPE**; each `de/<ns>.ts` is typed `: <Pascal>Messages` (imported from `en/<ns>.ts`) so a missing/mis-shaped key is a compile error. Interpolated strings are function entries (e.g. `exportedTo: (fmt, file) => …`). **Pitfall:** a bare ternary of string literals (`(n) => n === 1 ? 'word' : 'words'`) infers a literal-union return type — annotate `: string` so the German translation stays assignable.
- **`index.ts`** (main-safe, no Svelte) — merges `en`/`de` into `dictionaries`, exports `Locale = 'en'|'de'`, `Messages = typeof en`, `normalizeLocale()` (maps `'de-DE'`→`'de'`, else `'en'`), `resolveDict(locale)`.
- **`store.svelte.ts`** — the reactive layer (Svelte 5 runes), imported ONLY by `.svelte` files. `i18nState.locale` is the `$state`; **`t()` returns the active dictionary** — call `t().<ns>.<key>` inside a template/`$derived` and it re-renders on switch. `setLocale()` applies + persists via IPC; `applyLocale()` applies without persisting (boot path). Seeds from `navigator.language` to avoid a first-paint flash.

**Import rules (critical — `tsconfig.json` has no `paths`, so tsc can't resolve `@shared` in tsc-checked files):**
- `.svelte` files (not tsc-checked) → `import { t } from '@shared/i18n/store.svelte';`
- Plain `.ts` files (tsc-checked: editor node-views in `src/editor/lib/*`) → **relative** `import { t } from '../../shared/i18n/store.svelte';` — NEVER `@shared`.
- **Main process** must NOT import the rune store → `import { resolveDict } from '../shared/i18n'` + `getLocale()` from `persistenceManager`, resolved **at the call site** (`resolveDict(getLocale()).mainDialogs.x`) so it follows the live language. Used by `menuBuilder.ts` (native menu) and all `dialog.*` calls in `fileManager`/`projectManager`/`importExport`/`ipcHandlers`.

**Persistence + selection:** global (per-device) `locale` lives in electron-store (`persistenceManager.getLocale`/`setLocale`; `null` default → resolved from `app.getLocale()` on first launch). IPC `app:getLocale`/`app:setLocale` (whitelisted in `preload-entry.ts`); `app:setLocale` also calls `buildMenu(appState)` to relabel the native menu live. App.svelte loads the locale on mount. The **language dropdown is the "Interface" section of the Document Settings dialog** (`SettingsPanel.svelte`), bound straight to `setLocale` (independent of the per-document `onSave`). That dialog needs a project open — first-run language is OS-detected, so the StartScreen still shows in the right language without its own switcher.

**Conventions:** top-level computed text (label maps, option arrays) → wrap in `$derived(...)`; transient/handler strings → call `t()…` at call time. Reuse `t().common.*` only when the meaning matches exactly. Editor node-view popups (`editorLib`) read `t()` when their DOM is (re)built — already-open popups don't live-update (fine, they rebuild on reopen). To add a namespace: create `en/<ns>.ts` (+ `<Pascal>Messages` type) and `de/<ns>.ts`, then register it in **both** `en/index.ts` and `de/index.ts`.

### App ↔ MCP parity — the standing rule for anything touching both processes

The Electron app (`src/main`, `src/renderer`) and the MCP server (`src/mcp/server.ts`, a standalone Bun binary) are **two processes with no IPC between them**. They share exactly one thing: the project folder on disk. Everything either knows about the other goes through files.

> **The parity principle:** the AI (via MCP) sees what the human sees, and both describe the same files. Same knowledge, same access.

Four checkable demands, named this way throughout the repo:

| | | |
|---|---|---|
| **P1 Schreiben** | The same operation hits the same file with the same bytes and the same side effects from either side. | |
| **P2 Lesen** | Each side can fully read what the other produces. | |
| **P3 Wissen** | Both know the same state: which project, which file, unsaved edits, locks, does it compile. | |
| **P4 Schutz** | What is guarded on one side (verify, rollback, snapshot, guard) is guarded on the other. | |

**The pattern that works — use it instead of keeping two implementations in sync:** a **shared planner** in `src/shared/` that both processes call. Pure planning (`plan*` returns the writes), the caller decides how to apply them. Testable without Electron. Where this was applied, parity holds byte-for-byte and is measured by a test.

The shared modules, and what each stops from drifting:

| Modul | Löst |
|---|---|
| `safeApply.ts` | Staging → verify → commit/rollback. Verifier + IO injected. |
| `styleWrite.ts` | ONE write path for `style.json` / `style.typ` / root `#import`. Refuses on a hand-written `style.typ`. |
| `projectScaffold.ts` | ONE `scaffoldProject()` for all four creation paths (Git, `.gitignore`, `sources/`, `.penwright/`, skills, `style.typ`). Conservative defaults — it is reachable from "Save Version". |
| `assetPlacement.ts` | ONE image-placement rule: `<projectDir>/assets`, content dedup, never an overwrite, path relative to **the file holding the `image()` call**. Not "the open file" — reading it that way is what broke the macro file picker. An image node or a design-element snippet puts the call in the target file, so the base is that file; a **macro argument** travels to an `image()` inside the macro, so the base is the macro's defining file (`ProjectMacro.filePath`). Measured: `#let f(b) = image(b)` in `macros.typ` called from `chapters/c2.typ` wants `"assets/x.png"`, and `"../assets/x.png"` dies with `would escape the project root` pointing at `macros.typ`. |
| `popupPlacement.ts` | ONE rule for where a click-to-edit popup lands: below its anchor, flipped above when that does not fit, clamped to the viewport with a real `max-height`, and hysteretic so a growing textarea cannot flip it back and forth on one keystroke. Pure and in `shared/` for the same reason `macroFormFields` is — importing anything from `src/editor/lib/` pulls in the i18n rune store, and `$state` does not exist outside the Svelte compiler, so a node view's own geometry would otherwise be untestable. |
| `editHistory.ts` | The undo net: written and read by both, one retention limit. |
| `sessionState.ts` | `.penwright/session.json` + `<appData>/active-project.json` (app → MCP), `.penwright/agent-activity.json` (MCP → app, advisory). |
| `fileWrite.ts` | Write provenance by content hash — replaced the watcher's 3-second window. |
| `lockFile.ts` | Locks, incl. `isForeignEditor()` — **co-presence**: same person, two tools, is not a conflict. |
| `bibDiscovery.ts` · `stylePresetMerge.ts` · `printExportPlan.ts` · `watchIgnore.ts` | One rule each for the `.bib`, the preserve-list, the print switch, the ignore predicate. |

**What stays asymmetric on purpose — do not "fix" these:**
- The AI's **export sandbox is narrower**. The human picks a path in a dialog and owns the decision; a model must not write anywhere on disk.
- The **state channel is one-way** (app writes `session.json` / `active-project.json`, MCP only reads). A stale agent record must never steer the app. The back-channel (`agent-activity.json`) is display-only: the app shows it and obeys nothing.
- **Genuine foreign locks stay a hard refusal.** The co-presence fix only covers the same user on the same machine. No blanket `force` parameter for the AI.
- **No compile-verify before ordinary text edits** — on either side.
- **Two undo systems may coexist** (design-undo = verify-based; AI snapshots = content-based, per file). They solve different problems. They only have to be **visible from both sides**.
- **Web export has no MCP tool** (a product decision). Tool descriptions should *say so* rather than stay silent.

**Testing rule learned the hard way:** the lock test was green while the function was broken — it only ever checked `user: 'someone-else', machine: 'their-mac'` (the Dropbox colleague), never the everyday case of the same user on the same machine. **Test the most common case first.** And every fix gets a test that goes red without it (verified by reverting, e.g. the MCP rollback check in `parity-guards-test.mts`).

## Key Patterns

- **Preload whitelist:** any new IPC channel must be added to the allowed lists in `preload-entry.ts`. `SEND_CHANNELS`/`ON_CHANNELS` hold just the `Penwright` event channel; most new work goes into `INVOKE_CHANNELS`.
- **Typst 0.15 consequences worth knowing before you emit Typst.** A **backslash in a file path is now a hard parse error** ("path must not contain a backslash") — 0.14.2 accepted it on Windows, so anything that interpolates a computed path into `#image("…")` / `#include` / `#import` must normalise to forward slashes first (`markdownImporter.typstPath()`; `designElements.isPathParam()` covers 9 elements, and normalises BEFORE the `conditionals` table pre-renders `values.image`). The `pattern` type and the `path` element are **gone** (`tiling` / `curve`) — **bundled codly 1.3.0 still references `pattern` at three sites and 1.3.0 is the newest release**, so a user who passes a gradient/tiling to codly's `lang-fill` or a per-line highlight gets `unknown variable: pattern`; nothing we ship reaches those branches. Several **bibliography styles were renamed** (`vancouver` → `nlm-citation-sequence`, `council-of-science-editors` → `cse-…`, `modern-language-association-8` → `modern-language-association`) but the old names still compile with a deprecation warning, so no saved document breaks — `NUMERIC_BIB_STYLES` in `exportContext.ts` therefore lists **both** spellings, or the export would silently switch that document to author-year citations.
- **Typst compilation** always targets the root file (for multi-chapter support) and outputs PDF only. Never call `'typst'` directly — always use `getTypstPath()` so bundled-vs-system resolution works. For the args list, use `buildTypstCompileArgs(['<input>', '<output>'])` from `typstPath.ts`; it prepends `--package-path` so the bundled Typst packages (cetz, fletcher, showybox, codly, ...) resolve offline. The MCP server has its own `typstCompileArgs()` helper that reads `TYPST_PACKAGE_PATH` from env (set by the MCP setup wizard).
- **Preview-update mode (auto / manual)** — a **global** electron-store setting (`previewMode`, `persistenceManager.getPreviewMode`/`setPreviewMode`; IPC `persist:getPreviewMode`/`setPreviewMode`). It gates **only** the save-triggered recompile in `fileManager.saveFile()` (`if (getPreviewMode() === 'auto') compiler.compilePdf()`). The initial compile on open, external/AI watcher changes, and Undo-AI-Edit still recompile regardless (they're not "while typing"). In manual mode the file is still saved; the preview waits for the **Refresh button** (`preview:compile` IPC → `getCompiler().compilePdf()`). Chosen in the **Settings dialog → Preview** section. The renderer mirrors it in `previewState.mode` + tracks `previewState.dirty` (set on editor `onUpdate`, cleared on `previewPdfUpdate`/`compileError`) for the "Outdated" hint + Refresh-button accent.
- **Preview follows the active chapter** — on file switch the renderer sets `previewState.scrollTarget` to the open chapter's title (`firstHeadingTitle()` in `messageHandler`, computed in the `'update'` handler — fires on open/switch/external edit, never on keystrokes). It reads a native `= heading` first, then falls back to a `title: "…"` / `title: [...]` macro argument so magazine/design templates work too (e.g. `#opener(title: "Editorial")`, which still emits a real `heading` → PDF bookmark). `PdfPreviewPanel` reacts (effect guarded by `lastScrolledTarget` so it scrolls only when the target *changes*, never on plain recompiles), reads the PDF bookmarks via pdf.js `getOutline()`, fuzzy-matches the title, resolves the destination → page, and scrolls. Degrades to no-op if the PDF has no outline or no match. Still compiles the **whole** root doc (never a single chapter — that would drop global page numbers / styles / cross-refs).
- **Bundled fonts are VARIABLE** (`npm run fetch:typst-fonts` → `fetch-typst-fonts.mjs`), one file per style covering the whole `wght` axis, for six of the seven families; **Spectral is the exception** (no upstream variable build) and carries statics 400/500/600/700 + italics. This was static-only until Typst 0.15, whose lack of variable-font support was the documented reason — and it mattered because `styleTypes.ts` accepts nine named weights plus any numeric and the **default heading scheme uses `semibold` for h2–h4**, so with only 400+700 on disk every semibold heading in every new project silently rendered as bold (173 `semibold` + 40 `medium` requests across the shipped presets did the same). 0.15 also **trims `Variable`/`Var`/`VF` family-name suffixes**, which is what lets IBM's `IBM Plex Sans Var-Roman.ttf` register as the family `IBM Plex Sans` that presets already name. The script **prunes** files the manifest no longer lists — without that, statics would sit beside the variable file and Typst would register both under one family. Two presets ask `New Computer Modern` for semibold; that is Typst's *embedded* font and has only 400/700, so those six requests render bold and bundling cannot change it.
- **The bundled Typst compiler** is provisioned by `npm run fetch:typst` (`scripts/fetch-typst.mjs`), whose `TYPST_VERSION` constant is the **single source of truth for the version we ship** — currently **0.15.1**. It is the missing sibling of `fetch:packages` / `fetch:fonts`: the compiler used to be dropped into `resources/bin/` by hand, so only `typst-arm64-darwin` ever existed and a Windows or Linux or Intel-Mac build shipped **no compiler at all** — `getTypstPath()` fell through to probing the user machine and a clean install said "Typst not found", silently breaking the promise that Typst is bundled. `package:{mac,win,linux}` now run it for the target platform; `--check` verifies without downloading, `--all` fetches every platform. Only the host binary is committed (each is ~45 MB, and `extraResources` filters on `typst-*`, so every committed binary lands in every build).
- **Bundled Typst packages:** 24 packages live under `resources/typst-packages/preview/<name>/<version>/` (13 user-facing + 11 transitive deps). `scripts/fetch-typst-packages.mjs` pulls them from `packages.typst.org`. `scripts/audit-bundled-deps.mjs` runs as part of `package:*` and fails the build if any LICENSE classifies as GPL/AGPL or doesn't match its `typst.toml` declaration. The audit emits `THIRD_PARTY_LICENSES.md` at the repo root and `resources/typst-packages/bundle-licenses.json` for the in-app Acknowledgments dialog. Bundled list lives in the script's `PACKAGES` array — that's the single source of truth.
- **pdfjs `ArrayBuffer` is single-use:** `pdfjsLib.getDocument({ data })` transfers the buffer to the worker (zero-copy optimization), leaving it detached in the main thread. Re-calling `getDocument` with the same `data` throws `DataCloneError: ArrayBuffer is already detached`. When the document needs to update (zoom, scale changes), keep the loaded `currentPdf` and re-call `page.getViewport({ scale })` + `renderPage` instead of recreating the document.
- **Document zoom** is two independent levels: editor uses CSS `zoom: var(--editor-zoom)` on `.editor` (Chromium reflows the layout correctly, ProseMirror selection coordinates stay accurate — unlike `transform: scale` which breaks them); PDF uses pdfjs viewport scale `BASE_SCALE * pdfZoom` plus a proportional placeholder width so horizontal scroll kicks in above 100 %. Both are stored per-project in `.penwright/preferences.json` and shared between the live preview (`PdfPreviewPanel`) and source-PDF tabs (`PdfFileViewer`).
- **External file changes** are detected via chokidar; the watcher uses a 3-second timestamp guard (`lastSaveTimestamp`) to ignore self-triggered events. The watcher also ignores `**/.penwright/**` so backups never trigger refresh loops.
- **Five independent project-local persistence layers** — keep them mechanically separate (even though the first three are now *presented together* in the `HistoryDialog` hub — see Renderer components; the unification is presentation-only):
  - **Versions** (Git): user-triggered "Save Version" → `git commit`. Lives in `<project>/.git/`. Use the high-level handlers (`git:saveVersion`, `git:listVersions`, `git:restoreVersion`); the low-level verbs are kept for the "Advanced" cloud-sync UI only. **A project stays repo-less until its first version** — `git:saveVersion` lazily `git init`s (via `git:ensureRepo`) and `git add -A` commits everything, so this is the only path that works for projects opened from outside Penwright (e.g. magazine-pipeline output that ships without `.git`). `ProjectPanel` therefore enables "Save Version" when `!isRepo` (first commit) even with no file selected — earlier it gated on `git:status` returning changed files, which a repo-less project never does, so the first version could never be created.
  - **Auto-backups**: timer-driven multi-file snapshots in `<project>/.penwright/backups/<timestamp>/`. Each snapshot is a flat folder of files plus a `.meta.json`. On open, `checkForFileRecovery()` offers to restore if the latest backup is newer than the disk file.
  - **AI-edit snapshots**: `<project>/.penwright/ai-snapshots/`, one JSON per entry (`{ filePath, content, timestamp }`, `content` = the state BEFORE the edit). **The folder is the single truth and `src/shared/editHistory.ts` owns it — both processes write AND read it.** The app used to keep an in-memory ring buffer beside it that only ever held its own snapshots, so every file the agent rescued was invisible in the very UI built to surface it (`listSnapshots` had zero production callers). Scope is the **whole project**, not the open file: `ai:list` / `ai:undoLast` take an optional `filePath`, `popAiSnapshot(filePath?)` with no argument undoes the newest edit anywhere. MCP counterparts `penwright_list_edits` / `penwright_undo_last_edit`. **One retention limit, published by the app into the project**: `publishSnapshotLimit()` writes the user's configured `maxAiSnapshots` to `.penwright/ai-snapshots/.limit`, `snapshotLimit()` reads it (both processes), fallback `DEFAULT_SNAPSHOT_LIMIT = 40` — before this the app pruned to 20 and the MCP to a hard 40, so whichever wrote last imposed its own and the user's setting meant nothing. `takeLastSnapshot()` returns `{ snapshot, commit }` — the entry is deleted only after the caller's restore succeeded, so a half-failed undo does not consume its own way back. Never confuse with versions.
  - **Preferences**: `<project>/.penwright/preferences.json` holds per-project UI knobs (currently `editorZoom`, `pdfZoom`). Read/written via `getProjectPreferences` / `saveProjectPreferences`. Loaded on first `currentFile` event after open (cached by projectDir to avoid re-loads on file switches inside the same project); reset to defaults on `projectClosed`. Debounced save on change. - **Safe-apply engine ("every design change is a safe experiment") — now on BOTH sides of the process boundary.** The staging → verify → commit/rollback mechanic lives in **`src/shared/safeApply.ts`** (`safeApply({ writes, verify, baseline, io })`); everything process-specific is injected. It captures the previous state of every file, stages them all, verifies once, and on failure restores every one of them — a *partial* application is the failure mode it exists to prevent (exactly what `561c22e` fixed for `section:apply`, where the style files were written outside the staged set and survived a rollback that claimed to have undone everything).

It keeps what only main can do: syncing the open editor buffer, the **design-undo stack** (`design:undo` / `design:canUndo` → the DesignPanel "↩ Rückgängig" button), and showing the PDF the verify already produced.
